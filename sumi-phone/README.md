# Soto Phone

「楽しさは、画面の外に。」 SNS もゲームもない、必要な道具だけを持ち歩くデジタルデトックス・スマートフォンの紹介ページ。

## ページの流れ

- 1枚目と最後の先行予約：キャッチコピー「楽しさは、画面の外に。」
- 絵本の章（白黒の紙）：手描きスケッチから起こした物語
  - 机の前で終わりのないフィードをスワイプし続ける絵（フィードと指が動き続ける）
  - 部屋の絵では、窓の外が太陽から月へ変わり、夜はスマホの光だけが顔を照らす一日がくり返す
  - 絵の具が一滴落ちて、白黒の紙に最初の色がにじむ（スクロールで進む）
- 後半（手描きの線と水彩）：丘 → 湖 → 温泉 → 渓流 → 山 → 夕焼けの海と、だんだん色が増えていく
  - Soto Phone とは／入っている道具／ポイント／ショップ／かたち／先行予約
- 先行予約の登録フォーム（claude.ai の公開ページでは登録をページのデータベースに保存。ファイルを直接開いたときは保存されない）

コンセプト：必要な道具だけを持ち歩く電話。SNS・ゲーム・銀行・メール・QR 決済は入れず、支払いは実物のカード、ほかの用事はパソコンで。

`index.html`（日本語）または `en.html`（英語）をブラウザで直接開くだけで動きます。ナビの「EN／日本語」で切り替えられます。

## 画像の作り直し

- 後半の水彩の背景：`python3 tools/gen_watercolor.py images`（numpy と Pillow が必要）
- 絵本ページの紙：`python3 tools/gen_backgrounds.py images 10-paper`
- スケッチの切り出し：`python3 tools/clean_sketches.py images/story`（pillow-heif が必要。元の HEIC の場所はスクリプト内で指定）

## 一般公開して登録を集める

claude.ai のページは共有された人しか開けないため、だれでも登録できるように、サイトを一般公開し、登録を Google スプレッドシートに集める。

1. **登録の受け皿を作る（Google スプレッドシート）**
   1. Google ドライブで新しいスプレッドシートを作る（名前は「Soto Phone 先行予約」など）
   2. メニューの「拡張機能 → Apps Script」を開き、最初からあるコードを消して `tools/preorder-apps-script.gs` の中身を貼り付けて保存する
   3. 「デプロイ → 新しいデプロイ」で種類に「ウェブアプリ」を選び、「次のユーザーとして実行：自分」「アクセスできるユーザー：全員」にしてデプロイする（初回は Google アカウントの許可を求められる）
   4. 表示された ウェブアプリの URL（`https://script.google.com/macros/s/…/exec`）をコピーする。ブラウザで開くと `{"count":0}` と登録数が出る
2. **サイトに受け皿をつなぐ**：`script.js` の `const FORM_ENDPOINT` に、その URL を入れる（設定済み）
3. **サイトを公開する**：`sumi-phone` フォルダの中身（`index.html` `en.html` `styles.css` `script.js` `images/`）を静的サイトの置き場（Netlify、Cloudflare Pages など）にアップロードする。`tools/` は公開しなくてよい
4. 公開した URL からテスト登録し、スプレッドシートに1行増えることを確かめる（テストの行は消してよい）

登録は同じメールアドレスなら1行にまとまる。集めたメールアドレスは、フォームに書いた目的（発売と先行体験のお知らせ）以外には使わない。

## 登録した人に確認メールを送る

`tools/preorder-apps-script.gs` は、登録をスプレッドシートに書き込むと同時に、登録した人へ確認メールを1通送る（日本語で登録した人には日本語、英語の人には英語）。メールは Apps Script を動かしている Google アカウントの Gmail から送られ、送った日時が「確認メール」の列に入る。同じアドレスで登録し直しても、2通目は送らない。

1. スプレッドシートの「拡張機能 → Apps Script」を開き、コードを `tools/preorder-apps-script.gs` の最新の中身にまるごと貼り替えて保存する
2. 上の関数の選択で `testSendToMe` を選んで「実行」する。メール送信の許可を求められるので許可する。自分あてに確認メールが届けば成功
3. **「デプロイ → デプロイを管理」→ 鉛筆のマーク →「バージョン：新しいバージョン」→「デプロイ」**。これをしないと、サイトからの登録は古いコードのまま動く（URL は変わらないので、`script.js` は直さなくてよい）
4. サイトから自分のアドレスでテスト登録し、スプレッドシートに行が増えることと、メールが届くことを確かめる

- **送信の上限**：無料の Gmail から Apps Script で送れるのは1日100通ほど。いたずら対策で、1分に10通を超えた分は行だけ保存して送らない。送れなかった人には、`sendPendingConfirmations` を実行すると後からまとめて送れる（「トリガー」で1時間ごとに自動で動かしておくと安心）
- **前から登録されている人**：「確認メール」の列が空なので、`sendPendingConfirmations` を実行すると、その人たちにも送られる。テストで登録した行は、先に消しておく
- **文面の変更**：`mailJa` と `mailEn` の中を書き換え、もう一度3の手順で新しいバージョンをデプロイする
- メールの最後には「配信の停止・登録情報の削除」のリンクが入る。押した人は、確認の画面でボタンを押すと、「配信停止」の列に日時が入る（または行ごと消える）。お知らせを送るときは、「配信停止」に日時が入っている人を外す
- 「配信停止」とメールで返信があった場合も、同じようにその人の「配信停止」の列に日時を入れるか、行を消す
- `SENDER_ADDRESS` に住所（バーチャルオフィスでもよい）を入れると、メールの最後に所在地が出る。特定電子メール法で、お知らせのメールには送信者の住所を書く必要があるため、発売のお知らせなどを送る前に入れておく

## 法務・プライバシー

- `privacy.html` / `privacy-en.html`：プライバシーポリシー（Cookie、配信停止・削除、子どもの登録を含む）
- `terms.html` / `terms-en.html`：利用規約と、料金・返金の方針
- 内容を変えたら、ページの「最終更新」と `script.js` の `POLICY_VERSION` を同じ日付にそろえる（登録のときに、どの版に同意したかがスプレッドシートの「同意」の列に残る）
- Cookie もアクセス解析も使っていないので、Cookie のバナーは出していない。アクセス解析などを入れるときは、ポリシーを直し、同意のバナーを付けてから入れる
- フォントは `fonts/` からこのサイト自身が配信している（Google Fonts を使わないので、閲覧者の情報が Google に送られない）。どれも SIL Open Font License 1.1
