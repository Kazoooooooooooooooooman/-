## 1. パイプライン化 — 「仕組み」にする

これまでバラバラに動かしてきたものを、1本の流れにする:

```
generate_data.py   →  quality.db        (データ)
        ↓
analyze.py         →  metrics(集計・KPI)   (Day2-4)
        ↓
report.py          →  my_report.md + *.png (Day5-6)
```

理想は **`python3 run_all.py`** で全部が再生成されること。
これができると「毎週ボタン一つで品質レポートが出る」=オペレーションの自動化。

### run_all.py の骨組み(自分で完成させる)
```python
import subprocess
for step in ["generate_data.py", "analyze.py", "report.py"]:
    print(f"== running {step} ==")
    subprocess.run(["python3", step], check=True)
print("done. open my_report.md")
```

> 💡 「再現性」が肝。**誰が・いつ実行しても同じ結果**が出る(seed固定のおかげ)。
> これは品質オペで最重要の性質——監査に耐える。

## 3. 設計(System Design)の地図 — 深入りせず"概観"だけ

7日間ではここは**概念の地図を持つ**だけでいい(実装は今後の課題)。
ただし「何を今後学ぶか」が分かっていることが大事。

### 今のツールを「本物のシステム」にするなら
| 層 | 今(学習) | 本番だとどうなるか | 今後学ぶキーワード |
|---|---|---|---|
| データ取り込み | 手元のJSON/CSV | 相手企業の S3 から自動取得 | ingestion, ETL, 署名付きURL |
| 保存 | SQLite 1ファイル | PostgreSQL + クラウド | RDB, インデックス, 正規化 |
| 分析 | スクリプト手動 | スケジュール実行 | cron, ワークフロー(Airflow等) |
| レポート | md + png | BIダッシュボード | Metabase / Looker |
| 納品 | 手渡し | API + Webhook 自動通知 | REST API, 認証, バージョニング |
| 規模 | 数百行 | 数百万行 | スケーラビリティ, キャッシュ, キュー |

### 設計の「考え方」3原則(これだけ持って帰る)
1. **トレードオフで考える**:速さ・コスト・正確さは同時に最大化できない。何を優先するか。
2. **データの流れで考える**:入口(取り込み)→加工→保存→出口(納品)。どこが詰まるか。
3. **再現性と監査可能性**:誰がいつ実行しても同じ・誰が何をしたか追える(品質オペの命)。

### 今後の教科書(優先順)
- 『**Designing Data-Intensive Applications**』(Kleppmann)— データ系の聖典。最重要。
- 『**System Design Interview Vol.1/2**』(Alex Xu)— 実践・図解。
- **Use The Index, Luke**(無料)— DBインデックスだけ深掘り。
