# Day 6 — 伝える:分析を成果に翻訳する

> 🎯 今日のゴール:出した数字とグラフを、**意思決定者が動ける1枚のレポート**にする。
> 分析は「伝わって初めて価値」。ここが多くのエンジニアが弱く、PMが強い領域。
>
> 🏢 Mercorでの意味:*"develop, update, and regularly present leadership-facing reports"*(求人票)。
> リーダーシップは生データを見ない。**「で、何をすればいいの?」に答える1枚**が欲しい。
> これが書けると「分析できる人」から「**意思決定を動かす人**」になる。

所要:4時間。今日はコードより**言語化**が主役。

---

## 1. なぜ「分析」だけでは評価されないのか

よくある失敗:
- ❌「アノテーターMika_05の平均品質は56.3で、棄却率は100%でした」(事実の羅列)
- ✅「**棄却の40%が下位3名に集中。再研修でチーム棄却率を32%→20%に下げられる見込み**」(成果)

違いは何か:
1. **結論が先**(何をすべきか)
2. **数字が成果に結びついている**(◯%改善)
3. **行動が示されている**(再研修する)

---

## 2. Pyramid Principle(結論ファースト)

人に伝わる構造は**ピラミッド型**。上から下へ:

```
        【結論】 ← 一番言いたいこと(1文)
       /    |    \
   根拠1   根拠2   根拠3   ← それを支える3つの事実(数字)
     |       |       |
   詳細     詳細     詳細    ← 各根拠の裏付けデータ
```

> 💡 鉄則:**結論を最初に言う。** 「分析しました→こうでした→だから…」ではなく
> 「**こうすべき。なぜなら3つ。**」の順。忙しい人ほどこの順を求める。

例:
> **結論**:下位3名への再研修を最優先で実施すべき。
> - 根拠1:棄却の◯%がこの3名に集中(全体32% vs 該当者◯%)
> - 根拠2:3名に共通するエラーは `bad_transcript` と `missed_segment`(=研修可能な型)
> - 根拠3:3名は「作業時間が短い=rusher」傾向、急ぎが品質を落としている可能性

---

## 3. KPI の選び方 — 「動ける数字」だけ載せる

レポートに載せる数字は、**それを見て行動が変わるもの**だけ。

品質オペの代表KPI:
| KPI | 定義 | なぜ重要 |
|---|---|---|
| 棄却率 | rejected / 全audit | 納品品質の健全性。SLAに直結 |
| 平均品質スコア | AVG(quality_score) | 全体の地力 |
| 一発承認率 | approved / 全audit | 手戻りコストの逆数 |
| エラー種別TOP3 | error_type 別件数 | どこを研修/ガイド改善するか |
| 下位N名の寄与度 | 下位N名の棄却 / 全棄却 | 施策の費用対効果 |

> ⚠️ 「載せて満足する数字(vanity metric)」を避ける。
> 例:総セグメント数。多くても少なくても**だから何?**が無ければ載せない。

## 4. 1枚レポートの型(テンプレ)

`solutions/day6_report_template.md` にひな型がある。構成はこう:

```
# 週次 品質レポート — Batch B0X (2026-XX-XX)

## TL;DR(結論3行)
- 棄却率は 32%(目標 20% 未達)。主因は下位3名への集中。
- 再研修 + ガイドライン改訂で 32% → 推定 20% へ改善可能。
- hard タスクの品質が medium 比 -9pt。配分の見直しを提案。

## 1. 現状KPI(数字)
| KPI | 今週 | 目標 | 状態 |
|---|---|---|---|
| 棄却率 | 32% | 20% | 🔴 |
| 平均品質 | 75.1 | 80 | 🟡 |
...

## 2. Root-cause(なぜ)
- [散布図] 速い×低品質の象限に Mika_05, Nina_09… → rusher 仮説
- エラー内訳 TOP3: bad_transcript / missed_segment / wrong_emotion

## 3. 提案アクション(どうする)
1. 下位3名に bad_transcript 重点の再研修(今週)
2. missed_segment 多発 → ガイドラインに「無音区間の扱い」追記
3. hard タスクは senior 優先配分に変更

## 付録:図表
out_hist.png / out_scatter.png / out_errors.png
```

## 演習

1. Day5 の `my_report.py` の出力(表+図)を使い、**TL;DR 3行**を書け。
   結論ファーストで、各行に**数字**を入れること。
2. KPI 表を作れ(棄却率・平均品質・一発承認率・下位3名寄与度)。各KPIに目標値と🔴🟡🟢。
3. Root-cause を**3つ**、それぞれ図 or 数字を根拠に書け。相関を因果と断定しない言い回しで。
4. 提案アクションを**3つ**書け。各アクションは「誰が・何を・いつまでに・期待効果◯%」。
5. 全部を `my_report.md`(1枚)にまとめよ。**A4一枚で読み切れる**長さに削ること。
6. 仕上げ:そのレポートを**声に出して30秒で説明**する練習。詰まる所が弱い所。

> 🏢 面接シミュレーション:「このチームの品質、どう改善する?」と聞かれたら、
> この1枚を見せながら**結論→根拠3つ→アクション3つ**で答える。これが満点回答の型。
