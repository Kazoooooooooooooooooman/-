8よくある罠カタログ

バイブコーディングでハマる落とし穴は、実はパターンが決まっています。 ここに代表的な罠を集めました。「これ、今の自分だ」と思ったら、その場で対処法に飛んでください。 事前に知っているだけで、ハマる時間が数時間から数分に縮みます。

罠1：ハルシネーション（存在しないものを使う）

AIが、実在しない関数・ライブラリ・APIを、堂々と使ってくることがあります。

  • サイン： ModuleNotFoundError、AttributeError、「そんな関数ない」系のエラー。
  • 対処： その名前を公式ドキュメントで検索。無ければAIに「それは実在する？公式の名前を確認して」と問い直す。 実在する代替を出させる。

罠2：依存関係地獄（ライブラリが入っていない／合わない）

「動くはずのコード」が ModuleNotFoundError で動かない。多くはインストール忘れです。

# 「○○ が見つからない」と言われたら、まずインストール
pip install ○○            # Python
npm install ○○            # JavaScript / Node.js
バージョンずれの対処 「昔の書き方」をAIが使い、新しいライブラリで動かないことがあります。エラーに deprecated（非推奨）や 「○○ has no attribute」が出たら、AIに「使っているのは ○○ の v△ です。その版での正しい書き方にして」と版を伝える。

罠3：スコープ・クリープ（いつの間にか巨大化）

小さく始めたのに、AIに頼むたび機能が増え、コードが膨らみ、どこで何が起きているか分からなくなる現象。 対処：「動作確認1回分」を超えそうになったら立ち止まる（第5・9章）。今いらない機能は「後で」と断る勇気を持つ。

罠4：サイレント上書き（黙って別の所が変わる）

AIに「Aを直して」と頼んだら、ついでにBやCも書き換えられていた、というケース。 対処：変更を受け取ったら必ず git diff で全変更点を見る（第2章）。 意図しない変更があれば戻す。「ここだけ変えて、他は触らないで」と指示に明記する。

罠5：セキュリティの穴

動けばOK、で見落とされがちですが、これは取り返しがつかない事故につながります。最低限、次の3つだけは守ってください。

やってはいけない正しくは
APIキー・パスワードをコードに直書き環境変数や設定ファイルに分け、Gitに上げない（.gitignore）
秘密情報を含むファイルをそのまま公開リポジトリへ公開前に「鍵やパスワードが入っていないか」を必ず確認
ユーザー入力を無検証でDB・コマンドに渡す「この入力、危険な使われ方をしない?」とAIに監査させる
公開前の3秒チェック GitHubなどに上げる前に必ず ──「パスワード・APIキー・個人情報が含まれていないか?」。 一度公開した秘密は、消しても他人にコピーされ得ます。AIに「このコードに公開してはいけない情報は?」と聞くのも有効。

罠6：同じ堂々巡り（AIと無限ループ）

AIに直してもらう→別の所が壊れる→直す→また壊れる…の無限ループ。これはAIが全体像を見失っているサインです。

  • 一旦止める。 これ以上頼んでも泥沼。
  • 動く所まで戻す。 git restore . で直近の正常状態へ（第2章）。
  • 新しい会話で、現状を一から提示し直す。 混乱した文脈を捨てる（第5章）。
  • もっと小さく刻んで頼み直す。 一度に1つだけ。

罠7：「コピペで動いた」を理解した気になる

動いたコードを、中身を理解せずに積み上げると、壊れたときまったく手が出せなくなります。 対処：新しいコードを受け取るたび、第6章の「3点セット質問」で要点だけでも掴んでおく。 完全理解は不要だが、「ここが何の係か」は知っておく。後の自分を助けます。

この章の核 ハマりはパターン。実在を疑い（罠1）、入れ忘れを疑い（罠2）、肥大化を断り（罠3）、 git diffで監視し（罠4）、秘密を守り（罠5）、無限ループは戻ってやり直す（罠6）。 知っているだけで、沼の時間が桁で縮む。

章末チェック

  • 実在しない関数・ライブラリを疑い、確認できる
  • ModuleNotFoundError はインストールから疑える
  • 変更後は git diff で意図しない変更を見ている
  • APIキーやパスワードをコードに直書きしていない
  • AIと堂々巡りになったら、戻って仕切り直せる
