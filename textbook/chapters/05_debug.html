4体系的デバッグ ── 推測をやめ、検証する

直せない人は推測します。「たぶんここが原因かな」とあちこち書き換え、いつの間にか別のバグを増やします。 直せる人は検証します。仮説を立て、一つずつ確かめ、原因を物理的に追い詰めます。 デバッグはセンスではなく手順です。この章でその手順を丸ごと渡します。

デバッグの黄金ループ

あらゆるバグ取りは、結局この4ステップの繰り返しです。迷ったら、ここに戻ってください。

  • 観察： 何が起きているか、事実だけを書き出す。「期待＝○○、実際＝××」。
  • 仮説： 「○○が原因では？」と1つだけ立てる。複数同時に疑わない。
  • 検証： その仮説だけを確かめる小さな実験をする（値を表示する／一行だけ変える）。
  • 判定： 当たりなら直す。外れなら仮説を捨て、観察に戻る。ここで元に戻すのが超重要。
最大の禁じ手「同時に2つ変える」 原因が分からないからと、一度に複数箇所をいじると、直ってもなぜ直ったか分からず、また同じ沼にはまります。 一度に変えるのは1つだけ。外れたら戻す。これを守るだけで、デバッグ速度が倍増します。

武器1：二分探索（はさみうち）

「どこかで値がおかしくなる」「処理のどこかで止まる」── 範囲が広いときの最強の手法です。 全部を疑う代わりに、真ん中で半分に割る。これを繰り返すと、100行のコードでも7回で犯人に届きます。 

処理A → 処理B → 処理C → 処理D → 処理E   # どこかで壊れている

# 真ん中（C）の直後で値をのぞく
print("Cの後の値:", value)
   → ここで正常なら、犯人は D か E（後半）
   → ここで異常なら、犯人は A か B か C（前半）

# 生き残った半分の、さらに真ん中でまた割る。これを繰り返す。
コードだけでなく「変更」も二分探索できる 「昨日まで動いていたのに今日壊れた」なら、変更そのものを半分ずつ戻して原因を特定できます。 Gitでこまめにコミットしていれば（第2章）、どのコミットで壊れたかを git diff で挟み撃ちできます。

武器2：最小再現（小さく切り出す）

大きなプログラムの中でバグを追うのは大変です。そこで、問題の部分だけを取り出した、ごく小さなコードを作ります。 これを最小再現コードと呼びます。作る過程で原因が見えることも多く、AIに渡すときも精度が段違いになります。 

# 元：100行のアプリの中で、日付の計算だけがおかしい
# → 日付計算の部分だけ、5行に切り出して単体で動かす
from datetime import date
d = date(2026, 6, 8)
print(d)                 # まずここで正しいか確認
print(d.weekday())       # 次にここ。月曜=0 を知らないと「ズレてる！」と誤解する

武器3：仮定を疑う（思い込みリスト）

バグが見つからないとき、たいてい原因は「正しいと信じて確認していない場所」にあります。 次のような当たり前すぎて疑っていないことを、声に出して確認します。

思い込み実は…
「このファイルを実行している」別のファイル／古いファイルを動かしていた
「保存した」保存し忘れて、前のコードが動いていた
「この値はXのはず」表示してみたら全然違う値だった
「変更は反映されている」サーバ再起動が必要で、古い状態のままだった
「正しいコードを編集している」コピーした別の場所を直していた
魔法の質問 詰まったら自分にこう聞く ──「本当に？それ、自分の目で確認した？」。 “確認したつもり”を一つずつ“実際に確認”に変えていくと、たいてい犯人が顔を出します。

AIにデバッグを手伝わせる正しい頼み方

AIは優秀なデバッグ相棒ですが、丸投げすると暴走します。主導権はあなたが握ったまま、こう使います。

  • 「直して」ではなく「原因の候補を3つ挙げて」と頼む。判断はあなたがする。
  • 「このコードは何をしているか説明して」で、まず理解を補強する。
  • 「ここに print を入れるなら、何を表示すべき？」と、検証の設計を手伝わせる。
  • AIが大改造を提案してきたら一旦止める。原因が分かる前の大改造は、傷口を広げる。
この章の核 推測ではなく検証。一度に変えるのは1つ、外れたら戻す。 広い範囲は二分探索で半分に割る。複雑な問題は最小再現で小さくする。 そして「確認したつもり」を疑う。これがデバッグの全技術。

章末チェック

  • 観察→仮説→検証→判定のループを意識できる
  • 「一度に1つだけ変える」を徹底できる
  • 二分探索で原因の範囲を半分に絞れる
  • 問題部分だけの最小再現コードを作れる
  • 詰まったら「本当に？確認した？」と自問できる
