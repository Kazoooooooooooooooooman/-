付付録 ── 用語集 / 30分クイックスタート

最後に、つまずきやすい言葉を「ひと言」で引ける用語集と、 今日この場で安全網を張るための30分クイックスタートを置きます。 細かい正確さより、とりあえず話が通じることを優先した説明です。

30分クイックスタート ── 今日やる最小セット

まだ何も準備していない人へ。この順でやれば、30分で「事故らない体」になります。

  • （10分）安全網を張る。 プロジェクトのフォルダで git init → git add -A → git commit -m "最初の状態"。これで、いつでも戻れる起点ができた（第2章）。
  • （5分）テンプレを保存する。 第10章のテンプレ①（エラー修正）とテンプレ④（安全確認）を、メモアプリにコピーしておく。
  • （10分）小さく1つ作る。 ごく小さな機能を、第9章の9ステップで1周だけ回す。動いたらコミット。
  • （5分）わざと壊して、戻す。 コードを適当に壊し、git restore . で戻せることを体感する。 これで「壊すのが怖くない」状態が手に入る。
最初の一歩で十分 全部を完璧にやろうとしないこと。「戻れる」と「小さく回す」の2つさえ体に入れば、 あとは実戦の中で、この本の各章を必要なときに開けばいい。学びは、走りながらで間に合います。

おわりに ── 「直せる」はあなたの自由になる

この本が一貫して伝えてきたのは、たった一つのことです。 バイブコーディングの主役は、コードを生み出すAIではなく、それを見て、確かめて、直せるあなただということ。

作る速さは、もう手に入りました。次に手に入れるべきは、壊れても怖くないという自由です。 その自由は、新しい才能ではなく、この本に書かれた地味な手順の習慣化から生まれます。 エラーを一番下から読む。一度に1つだけ変える。動いたらコミットする。確認するまで完成と言わない。

どれも派手ではありません。けれど、これを淡々と続けられる人だけが、 AIを「魔法」ではなく「道具」として使いこなし、自分の作りたいものを、最後まで自分の手で完成させられます。

最後に、これだけ持ち帰る 戻れるようにして（Git）、小さく回し（ワークフロー）、エラーは読み（第3章）、推測せず検証する（第4章）。
この4つができれば、あなたはもう「自分で直せる人」です。あとは、手を動かすだけ。
