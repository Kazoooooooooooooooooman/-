9実践ワークフロー ── 1機能を完成させる流れ

ここまでの技術を、ひとつの流れに組み立てます。これは、直せる人が 新しい機能を1つ作るときに、無意識でなぞっている手順です。 そのまま真似してください。最初は遅く感じても、これが結局いちばん速い道です。

1機能を作る9ステップ

  • ゴールを一文で書く。 「ユーザーが問い合わせを送れるようにする」。曖昧なら、まだ始めない。
  • 動作確認1回分まで割る。 「①フォーム表示 → ②送信受取 → ③保存 → ④完了表示」。今日は①だけでもいい。
  • 始める前にコミット。 git add -A && git commit -m "○○の前"。避難先を確保（第2章）。
  • 5要素でAIに頼む。 目的・文脈・制約・入出力・形式（第5章）。小さく、1ステップ分だけ。
  • 受け取る前に説明させる。 「これは何をする?危険はない?」（第5・6章）。
  • 動かして確認する。 正常・空・変の3パターン（第7章）。エラーが出たら第3・4章へ。
  • 動いたら即コミット。 セーブポイント確定。これで①が「壊れない資産」になる。
  • 次のステップへ。 ②に進み、4〜7を繰り返す。一段ずつ確実に。
  • 全部つながったら、通しで回帰チェック。 端から端まで動かし、副作用を確認（第7章）。
このループの肝 「頼む → 理解する → 確かめる → 保存する」の小さな円を、何度も回すこと。 一周がどんどん小さく速くなるほど、事故っても失うものが減り、原因も一瞬で分かるようになります。 バイブコーディングが速い人は、大きく作る人ではなく、小さい円を高速で回す人です。

つまずいたときの「判断フロー」

作業中に手が止まったら、考え込まず、この分岐を上から当てはめてください。

「行き詰まりタイマー」を使う

一人で（AIと）粘る時間には上限を決めます。おすすめは15分ルール。 同じ問題で15分進展がなければ、やり方を変えます ── 戻る、最小化する、別の聞き方をする、休む。 同じ方法で粘り続けるのが、最も時間を溶かします。

休憩は最強のデバッグ どうしても解けないとき、5分席を立つと、戻った瞬間に原因が見えることがよくあります。 脳が裏で整理してくれるからです。詰まったら粘らず、一度離れる ── これも立派な技術です。

1日の終わりにやること

  • 動く状態でコミットして終える。 翌日「動く所」から再開できる。
  • 次にやることを一行メモ。 「次：保存機能の異常系を試す」。再開が一瞬になる。
  • 未解決の謎を書き残す。 寝かせると翌朝あっさり解けることがある。
この章の核 頼む→理解→確かめる→保存の小さな円を高速で回す。 詰まったら判断フローを上から当てる。15分ルールで粘りすぎない。 1日を動く状態で終える。これがバイブコーディングの基本動作。
