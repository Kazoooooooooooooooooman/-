6コードを「読める」最低限

直すために、コードを書ける必要はありません。必要なのは、AIが出したコードを見て 「だいたい何が起きているか」を追えること。全文の翻訳ではなく、流れを追う「速読」です。 ここでは、言語が違っても共通する“読みの骨格”だけを、最短で渡します。

プログラムは「上から下へ」流れる

ほとんどのコードは、上から順に、一行ずつ実行されます。まずこの感覚を持つだけで、 「どこまで進んで、どこで止まったか」が追えます。エラーの行番号が効くのも、この性質のおかげです。

どの言語にもある「5つの部品」

言語が違っても、コードは結局この5部品の組み合わせです。これさえ見分けられれば、流れは追えます。

部品役割見た目（例）
変数値に名前をつけて入れる箱name = "佐藤" / let count = 0
関数処理のまとまり。呼ぶと動くdef save(x): / function save(x){}
条件分岐「もし〜なら」で道を分けるif age >= 18:
繰り返し同じ処理を何度も回すfor item in list:
呼び出し他の機能を使うsave(user) / print(x)
5部品で読んでみる 
total = 0                      # 変数：合計を入れる箱、最初は0
for price in cart:             # 繰り返し：カートの各値段について
    total = total + price      #   合計に足していく
if total >= 5000:              # 条件：もし合計が5000以上なら
    print("送料無料")          #   送料無料と表示
日本語にすると「カートの値段を全部足して、5000以上なら送料無料と出す」。 一語一語の文法を知らなくても、流れは読めます。これで十分です。

「名前」を信じて読む

良いコードは、変数や関数の名前が中身を語ります。send_email はメールを送る、 is_valid は正しいかどうかを表す。細部が分からなくても、名前から役割を推測して流れを追えます。 逆に、AIが付けた名前と動きが食い違っていたら、それ自体がバグのサインです。

分からない一行は「AIに通訳させる」

読めない行が出てきたら、止まらずにこう聞きます ── 「この行が何をしているか、初心者向けに1文で説明して」。 これを繰り返すうちに、同じパターンが読めるようになり、聞く回数は自然に減っていきます。

読みの3点セット質問

① 「このコード全体を、3行で要約して」（地図をもらう）

② 「○○ の行は何のため？」（気になる所だけ深掘り）

③ 「もしこの行を消したら何が起きる？」（その行の存在理由を知る）

「データの形」を意識する

不具合の多くは、データの形の思い違いから生まれます。 一個の値なのか、リスト（並び）なのか、辞書（鍵と値の対）なのか。これを取り違えると TypeError 系が出ます。 読むときは「今この変数には、どんな形のデータが入っている？」を常に意識します。迷ったら表示して確かめる（第3章）。 

user = "佐藤"                          # 1個の文字列
users = ["佐藤", "鈴木"]               # リスト（並び）。users[0] が "佐藤"
user = {"name": "佐藤", "age": 30}     # 辞書。user["name"] が "佐藤"
この章の核 コードは上から下へ流れる。中身は5部品（変数・関数・条件・繰り返し・呼び出し）。 名前から役割を推測し、分からない行はAIに通訳させる。データの形を常に意識する。 書けなくても、これで「追える」。
