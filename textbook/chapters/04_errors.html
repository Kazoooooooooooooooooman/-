3エラーメッセージを読む技術

これは本書で最も価値のある章です。なぜなら、エラーの9割は、メッセージ自身が答えを書いているからです。 読めないのは、英語が読めないからではありません。どこを、どの順で読むかを知らないだけです。 順番さえ覚えれば、長い赤文字は「事件現場の地図」に変わります。

エラーメッセージは「3つの情報」でできている

言語が違っても、エラーはほぼ必ず次の3点を含みます。まずこの3つを拾うことだけ考えてください。

拾う情報意味探し方
① 種類（Type）何系の問題か（名前が無い／型が違う／構文ミス…）多くは行頭の ○○Error
② 場所（Where）どのファイルの何行目かfile.py や line 42 の表記
③ 説明（Message）具体的に何が起きたか（人間向けの一文）Error名のすぐ後ろ／一番下の行
読む順番（これだけ覚える） ① 一番下から読む。 ② エラーの種類と説明文を拾う。 ③ 自分のファイル名がある行を探す。
上から順に全部読もうとすると挫折します。多くの言語で、結論は一番下にあります。

実例で読んでみる（Python）

Traceback (most recent call last):
  File "app.py", line 3, in <module>
    print(user_name)
NameError: name 'user_name' is not defined

一番下から読みます。

  • 説明： name 'user_name' is not defined ＝「user_name という名前が定義されていない」
  • 種類： NameError ＝ 名前（変数）まわりの問題
  • 場所： app.py の line 3

つまり「app.pyの3行目で、user_name という変数を使おうとしたが、そんな変数は作られていない」。 原因はたいてい タイプミス（username と書くべきだった）か、定義し忘れ。これで対処は決まります。

よく出るエラーの「翻訳辞書」

初学者が出会うエラーの大半は、次の顔ぶれの繰り返しです。これはそのまま使える早見表です。

エラー表記（言語）日本語の意味まず疑うこと
NameError / ReferenceError (Py/JS)その名前が見つからないスペルミス・定義忘れ・スコープ外
SyntaxError文法が壊れている括弧 () や {} の閉じ忘れ、コロン・カンマ
TypeError型が想定と違う文字列と数値の混同、None/undefined を操作
IndentationError (Py)字下げがおかしいスペースとタブの混在、ずれ
ModuleNotFoundError / Cannot find moduleライブラリが見つからないインストール忘れ（第8章）、名前間違い
KeyError / undefined (is not ...)その鍵・属性が存在しないデータの形が想定と違う、綴り違い

スタックトレースの「自分の行」を探す

長いエラー（スタックトレース）は、プログラムが通った道のりを上から並べたものです。 その多くはライブラリ内部の行で、あなたが直す場所ではありません。コツは一つ。

魔法の一手 長いトレースの中から、自分が書いた／AIが書いたファイル名（例：app.py, main.js）が 出てくる一番下の行を探す。そこが、あなたが手を入れるべき現場です。 ライブラリの奥深く（site-packages/... や node_modules/...）は、たいてい通り道にすぎません。

エラーが「出ない」不具合の見つけ方

やっかいなのは、エラーは出ないのに結果がおかしいケースです。こういうときは、自分でエラーの代わりを作ります。 最も原始的で、最も効く道具が 途中経過の表示 です。 

# 値が想定どおりか、要所要所で「のぞき見」する
print("ここまで来た。userの中身は:", user)        # Python
console.log("calcの結果:", result);              # JavaScript

「思っていた値」と「実際に表示された値」がズレた地点 ── そこと、その直前が犯人です。 プロも日常的にこれをやります。恥ずかしいことではありません。第4章でこの考え方を「二分探索」として体系化します。

エラーをそのまま検索・質問する技術

意味が分かっても解けないときは、調べる・聞く。その渡し方で結果が大きく変わります。

  • 検索するなら： エラーメッセージの固有の部分（自分のファイル名や具体値）を消し、 一般的な部分だけをコピーして検索する。例：TypeError: cannot read properties of undefined reading map。
  • AIに聞くなら： エラー全文を省略せずそのまま貼る。一番下だけでなく全体を。 さらに「何をしようとして」「何が起きたか」を添える（テンプレは第10章）。
やりがちなNG エラーの一部だけスクショして「これ直して」と渡す。AIは場所も文脈も分からず、当てずっぽうで返してくる。 テキストで全文＋直前にやったこと。これだけで返答の精度が跳ね上がる。
この章の核 エラーは「種類・場所・説明」の3点セット。読むのは一番下から。 長いトレースは自分のファイル名の最下行が現場。エラーが出ない不具合はprint/console.logでのぞく。
