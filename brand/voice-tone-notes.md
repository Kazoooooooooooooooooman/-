# ボイス＆トーン 学習ノート

一真さんが共有している書籍（Part 1「ボイス＆トーン」、第1章「ボイス＆トーンのデザイン」）の要点を、自分の言葉でまとめたもの。

## 1. なぜボイス＆トーンが大事か

- 人はコンピュータや画面の向こうの言葉にも、人間に対するのと同じ社会的なルールで反応する（スタンフォード大のクリフォード・ナス教授らの研究）。
  - 礼儀正しさ、ほめてくれること、温かい反応を期待する。
  - 期待に合わない振る舞いをされると、気分を害し、失望し、反感を持つ。
- 人は、話しかけてくる存在を「一貫した一人の人格」として捉えようとする。人格が描けないと、怪しみ、受け入れにくくなる。
- **見た目（非言語）と言葉（言語）が食い違うと、信頼されない。** 一致して補い合っていると、知的で楽しく、説得力があると受け取られ、行動まで変わる。
- 事例：大手通信会社。見た目や UI は革新的なのに、言葉は15年前の定型文のまま（「貴重なお問い合わせを…」「登録が無事に完了しました」「データをダウンロード中です。少しお待ちください」）。差別化したいのに、誰もが使う言葉しか使っていなかった。

**Soto への示唆：** 今のサイトと SNS は、見た目（紙と墨、映画風）と言葉（説明調、ネタ寄り）がずれている。ブランドガイドライン v0.1 で指摘した「二つの世界」の問題と同じ。

## 2. ボイス＆トーンとは

ブランドがユーザーと話すときの言葉の使い方を決める作業。目的は、言葉をブランド価値と一致させ、不協和音や不信感を生まないこと。言葉は二つの基準で選ぶ。

1. **パーソナリティ**：礼儀の度合い、ユーモアの量、スラングを使うか、伝える速さ、感情の出し方、どこまで友だちのように話すか。
2. **メッセージ**：主要なメッセージは何か。行動を促すために何を強調するか。ユーザーが自分自身とブランドの両方を肯定的に感じられるように、何を言えるか。

同じ内容でも、個性で言い方は変わる（例：生年月日を聞く理由。Nike は「COPPA を順守するため必要です」と誠実に。J.ピーターマンは「すみません、弁護士に聞けと言われたので」と打ち解けて）。違いは、ユーザーとどんな関係を築きたいかから来る。

決まったら、すべての言葉がこの指針で選ばれる → 目的に合い、価値が伝わり、行動喚起がシンプルになり、信頼される。

## 3. いつデザインするか（7つの局面）

1. 新規ブランドを立ち上げるとき（ビジュアルと並行。早いほど良い）
2. 新しい／改良版のプロダクトを出すとき
3. 差別化を強めるとき
4. 新しいデジタルキャンペーンをするとき
5. メール、チャット、SNS などの発信の仕組みを作る・更新するとき
6. 新しい市場・ターゲットに入る前
7. 今の言葉がうまく機能していないと気づいたとき

**Soto は 1・6・7 に同時に当てはまる。** 名前の変更、ターゲットの決定、リールが伝わらないという友人の指摘。今が一番やるべき時期。

## 4. 進め方（4ステージ、全体で1〜3週間）

成果物は「ボイス＆トーンのスタイルガイド」。マイクロコピー、コピー、SNS の投稿など、ブランドが出す言葉すべてに使う。
小規模事業なら、**少なくともステージ2と3はやる**。

| ステージ | 内容 |
|---|---|
| 1. ブランドを知る | 既存資料を読む：ビジョン・ミッション・価値、ブランドブック、スタイルガイド、会社紹介資料、UX コンセプトとペルソナ、ブランド認知や満足度の調査 |
| 2. ユーザーを知る | ユーザーの発言の引用、繰り返し使われる言葉を集め、やる気が上がる／下がる要素を見つける（情報源は p.37 TIP05 ※未読） |
| 3. 関係者インタビュー | 質問リスト（p.48〜49）でグループインタビュー。約3時間、または2時間×2回（1回目ブランド、2回目ユーザー）。小規模なら主要メンバーは創業者。チームや友人、アドバイザーを呼ぶ。1対1を繰り返すより、グループで見解の違いをその場で解消する |
| 4. 統合 | すべてをまとめてスタイルガイドにする（完成形は p.46 ※未読） |

## 5. ステージ1の中身

### 5-1. ビジョンとミッション
- ユーザーに直接見せることは少ないが、**書く言葉はすべてビジョンとミッションを推し進めるものでなければならない。** だから書き手は隅々まで理解しておく。
- ビジョンを定義するのは思ったより難しい。時間をかける。
- **TIP01 なぜなぜ分析**：「なぜこのブランドを作ったのか」と聞き、答えに「なぜ？」を繰り返すと核心にたどり着く。
- 実例：IKEA（より快適な毎日を、より多くの方々に）、TripAdvisor、Samsung、WWF。
- TIP02：既存の資料（ブランドブック、ピッチ資料、投資家向け資料）を探し、今も有効か確かめ、違えば手直しする。

### 5-2. 価値を定義する
- 最重要の価値を **5つ** 選ぶ（候補は「116の価値」リスト：楽しさ、冒険、自由、遊び心、簡潔、本物、心地よさ、平和・落ち着き・安らぎ、勇気、結びつき、健康、優しさ、節度、発見 など）。
- それぞれを **1〜3行** で説明し、「この価値をうまく伝える言葉は何か」を考える。
  - 例：リーダーシップ → カリスマ性、切れ味、意欲を刺激する言葉。
  - 例：コミュニティ → 懐が深くつながりを感じる言葉、温かい雰囲気、控えめなユーモア、共感や心配り。
- **TIP03 言葉のツールボックス**：価値ごとに、関連する単語・熟語・言い回しを集めておく。類語辞典に加えて、**ユーザーから直接聞いた言葉**も記録する。
- 実例：NPR（正確さ、自主独立、敬意、責任、優れた品質）、Whole Foods。

### 5-3. パーソナリティを言葉で伝える
- ブランドを一人の人間として想像し、性格、人との接し方、ユーモアの有無、服装、趣味などを書き出す。そこから話し方を想像する。
- **注意：ブランドの個性とユーザーの個性は別物。** ユーザー像は、どんな関係を築きたいかで変わる（p.44 ※未読）。
- **TIP04 評価尺度**（パメラ・ウィルソン）：6本の軸で、ブランドがどこに立つかを決める。
  - 飾り気なくフレンドリー ↔ 仕事優先、プロ意識
  - 本能的、エネルギー旺盛 ↔ じっくり考える、計画的
  - モダン、ハイテク ↔ クラシック、伝統的
  - 最先端 ↔ 既存の秩序
  - 面白い ↔ 真面目
  - 手ごろ ↔ 高級路線
- 実例：睡眠コンサルタント。ターゲットは情報の洪水で自信を失った初めての母親。ブランドを「35歳、子どもがいて、着心地が良くおしゃれな服、育児とヘルスケアの記事を真っ先に読む、話をよく聴き上から目線にならない人」と設定。言葉への反映：
  - 深刻になりすぎず、ユーモアを交えて軽やかに。
  - 専門知識で信頼を示すが、教え諭す態度は避ける。
  - 得られるものを一目でわかるリストにする。
  - 母親を主人公にして語る。
  - フレンドリーとプロ意識のちょうど真ん中。同輩として接するが「最良の友人」の立場はとらない。

### 5-4. ユーモアを入れるときの7つのヒント（p.30〜31）
1. **ブランドの個性に合わない言い方をしない。** 気の利いた言い回しを考える前に、どの価値がなぜ大事かを確かめる。ただし「深刻な分野だから真面目に」という先入観にも注意（糖尿病の食事管理アプリでも、ユーモアで試練の日々を笑顔で乗り切る応援はできる）。
2. **ターゲットに受け入れられない言い方をしない。** 文化、年齢、方言に合っているか。若い世代向けなら、同じ年ごろの人に読んでもらって違和感がないか確かめる。
3. **ユーモアだけが読みどころにならないように。** 味わいは他にもある（ノスタルジック、ほのぼの、控えめ、脱力、キレの良さ、我が道を行く…）。ユーモア以外が何も伝わらないなら、ずれている。
4. **どこまでがやりすぎか。** オチで締めるなら入り口はシンプルに。全体を一つの流れにすると、上質なユーモアを散りばめやすい。Google の言い方：森に一角獣がいるなら、芸をするサルは要らない。
5. **分かりやすさを犠牲にしない。** 読み直さないと分からないなら失敗。ユーモアは「簡潔・明快・有用」の相棒にはなるが、代わりにはならない。
6. **状況をよく考える。** データが消えたような場面で冗談を言わない。
7. **ジョークを詰め込みすぎない。** 3回目くらいで楽しめなくなる。

**Soto への示唆：** 友人の「面白いリールで終わってしまう」という指摘は、3（ユーモアだけが読みどころ）と5（分かりやすさの犠牲）にそのまま当てはまる。

## 5B. ステージ2：ユーザーを知る（p.32〜42）

### 1. 人口構成を明らかにする
- 年齢、性別、生活圏、教育レベル、配偶者の有無、他の興味、テクノロジーへの関心度を調べる。
- 若い世代には流行り言葉が使えるが、上の世代には通じにくい。層が限られるなら、その層で人気の番組のセリフなどでスパイスを利かせる手もある。
- **ターゲットが幅広いなら**、控えめでオーソドックスなボイス＆トーンにする。それでも単調にせず、ペルソナに合う味わいを持たせる（例：IKEA は抑制がきいて特にユーモラスでもないが、一貫した心地よさと家庭的な温かさがある）。
- **ターゲットが性質の違う複数のグループに分かれるなら**（例：売り手と買い手、10代とファミリー層）、ブランドの個性は一つのまま、グループごとにメッセージの書き方を変える。

### 2. ニーズと問題を見極める
- 操作で何に手こずり、気持ちの上で何が負担か。**彼ら自身の言葉で聞く。**
- これは言葉で人を操ることではない。プロダクトが本当に問題を解決しないなら何もうまくいかない。目指すのは、問題を正確に特定し、ユーザーの言葉で表現し、解決策を選んでもらうこと。
- 実例（求人サイト）：
  - 職探しは平均60日続く消耗戦 → なぜその入力が必要か、それが目標への一歩になることを都度説明。ただし繰り返しにならないよう、簡潔で前進やスピードを表す動詞を使う。
  - 群衆に埋もれる恐れでやる気を失う → カバーレターの入力欄の直前に、状況に率直に触れつつ「頭一つ抜け出す得策」だと伝える。
  - 孤独 → 会話体のやわらかい雰囲気で寄り添い、共感を伝える。
  - 送信しても反応がなく不安 → 操作のたびに「確実に受理されました」など簡潔なフィードバックを出す。

### TIP05 ユーザーは最良のコピーライター
- ユーザー自身の言葉をそのまま使うのが一番正確で、本人ならではの表現になる。
- 聞ける場所：チャット記録、アンケートの自由回答、関連テーマのオンラインコミュニティ、SNS上の自社や競合へのコメント、ユーザビリティテスト、コールセンター、フォーカスグループ、ターゲットがそのテーマを語るあらゆる場所。
- **資料が何もない場合**：見込み客や友人・家族5〜10人に1〜2時間インタビューする。それだけでも認識とコピーが劇的に変わることがある。
- 見つけた言葉は宝物。そのまま引用してマイクロコピーに織り込む。

### 3. 夢や希望を言語化する
- セクション2はネガティブ（問題の解決）、セクション3はポジティブ（どんな収穫が得られるか）。
- 人が行動するのは、それで夢や希望に近づけると信じるから。行動を促したいときは、彼らの夢や希望を語る。
- 実例（銀行の家計管理ツール）：顧客の願いは「心の平和と私財の保護」「家計の全体像の把握」「QOL の向上と夢の実現（例：オーロラ観賞の旅）」。各機能の説明をこの願いに結びつけて書いた。
- キャッチフレーズに頭を抱える必要はない。ユーザーは何かを達成したくて来ている。それが何かを明らかにし、思い出させるだけでいい。

### 4. 行動を阻む要因を見極める
- マイナス要因から目を逸らさず、真正面から（少なくとも婉曲に）取り上げるほうが軽減につながる。
- どこにでもある障壁：お金の負担、個人情報を出す抵抗感。そこに製品特有の障壁が加わる。両方をリスト化し、納得できる理由を添えて伝える。
- 実例（婚約指輪サイト）：好みやサイズが分からない、ダイヤの見分け方が分からない、断られたら指輪はどうなるか、ネット購入の不安。→ 選ぶ前に「彼女のジュエリーボックスを見ておこう」と提案、サイズ変更は無料、専門用語は実例付きで説明、鑑定書の見本、30日以内なら全額返金を明記。
- 障壁は体系的にリスト化し、適切なタイミングで解決策を出す。

### 5. 他社ではなく自分たちを選ぶ理由を調べる
- 競争優位性をメッセージにして繰り返し伝える。
- 実例（イスラエルの大学）：志願者は情報の洪水で、間違った選択を怖れている。競争優位性のリストを作り、そこから項目を抜き出して歓迎の文章を書いた。リストさえあれば、あとは言葉にするだけ。
- **TIP06 ユーザーを主体に**：伝えるのはブランドの利点ではなく、ユーザーにとっての利点。新しい技術も、それでユーザーが以前できなかったことができるなら初めて意味がある。大事なのは結果。

### 6. ユーザーとの関係性を定義する
- どんな関係を築きたいかを描き、すべての言葉がそれを支えるようにする。
- 例：友人、親友、師弟、目的を共有する人々、両親、知人、ビジネスパートナー、指導者と支持者、売り手と買い手、スターとファン、カップル、管理職と個人秘書。
- 実例（B4U ペイ）：ユーザーとサービスは「同じサイドで戦うひとつのチーム」。あらゆる場面でこの協力関係に触れた（「さあ、椅子にゆったり身を預けてください。ここからは私たちが…」）。

### まとめ：スタイルガイドの形
- 書き方や様式に決まりはない。プロジェクトに合う資料を作る。
- 例：章の内容をすべてまとめた内部向けの作業マニュアル。多くの組織はそれで十分。
- 多くの媒体（サイト、マイクロコピー、SNS、メルマガ、チャット）で多くの書き手に統一してほしいなら、事例を添えた正式なガイドブックにする。形式は文書、プレゼン、ウェブサイトなど自由。
- 参考になるスタイルガイド：リーズ大学、メールチンプ（voiceandtone.com）、セールスフォース（第19章）。

### スタイルガイドの使い方
- **指針として**：どんなスタイルで書くか。前もって読み込んでおき、書くときにざっと見返す。
- **判断基準として**：どんな内容を書くか。行動の動機づけ、障壁の取り除き方、どのメッセージが効くかに迷ったら開く。
- 作ること自体が目的ではない。作っても実践できないブランドは多い。書く習慣は根深く、使い慣れた言い回しに戻ってしまうから。
- 作るのは入り口にすぎない。ブランドそのものになったつもりで書き、古いやり方に戻らない。

### コラム：登録 vs. サインアップ vs. 参加する
- 「サインアップ」：手続きが簡単で速い印象。
- 「登録」：入力項目が多い手続き向き（銀行、保険など）。
- 「参加する」：サービスを受け取るだけでなく、コミュニティに加わる感覚を伝えたいとき。
- 「サインアップ」と「サインイン」は並べない（区別しにくい）。サインアップと組むなら「ログイン」。色を変えるとさらに区別しやすい（PayPal、Coursera）。
- 一度決めた言葉は、すべての箇所で統一する。

## 7. 第2章 会話体ライティング（p.50〜56、途中まで）

- デジタルプロダクトは、公開した日からブランドを代表する接客係になる。訪問者に挨拶し、紹介し、使い方を説明し、別れの挨拶をする。
- 理想の接客係：誠実な笑み、心から力を貸す、自分とブランドへの誇り、相手への敬意、緊張をほぐす小さなジョーク。「大勢の客の一人」だと忘れさせてくれる人。
- **インターフェイスの言葉は、対面で顧客に語りかける言葉と同じ働きをする。** 嘘やごまかしのない、心のこもった人間らしい言葉を使えば、お堅い組織でも体験は良くなる。
- 現実のプロダクトの多くは機械的で堅苦しい（「エラーです、もう一度お試しください」「有効なメールアドレスを入力してください」）。
- 書き言葉（形式的）と話し言葉（気さく）の壁は、ネットとチャットで崩れた。第三の選択肢＝**会話体ライティング**。話すように書く。
- **ただし不適切な言葉は厳禁。** 不適切とは、ぞんざい、不正確、誤解を生む、文法が崩れた、一貫性のない言葉。会話体の言葉は、丁寧で敬意にあふれ、文法的に正しい。上質な言葉とは、厳格でかしこまった言葉のことではない。
- インターフェイスは両面を持てるし、持つべき：思慮深くて楽しげ、知的で笑顔、礼儀正しくて人当たりが良い。

### ルール1：会話では口にしない言い方をしない
- 例（左が堅い書き言葉、右が会話体）：
  - ダイヤルしたい電話番号を入力してください → 何番におかけですか？
  - 登録を完了している方はメールとパスワードを… → ユーザー登録はお済みですか？ それではメールアドレスとパスワードを入力してください
  - 確認のためご指定のアドレスにメールが送られます → 確認メールを送信しました
  - 電話での購入申し込みも可能です → 商品のご購入は、電話でも承ります
  - あなたが購入を希望する製品 → あなたのお買い物リスト
  - パスワードをお忘れの場合 → パスワードをお忘れですか？

### ルール2：文章の構造の違いを意識する
- 書き言葉は受動態が多く、話し言葉は能動態が多い。
  - 「望ましいと思われる支払い方法をお選びください」→「どのような支払い方法をご希望ですか？」または「支払い方法をお選びください」
- **マイクロコピーでは常に能動態。** 相手を主語にする。

### 優れた会話体のためのヒント
1. **思い浮かんだままの言葉を使う。** ユーザーが目の前にいると想像し、どう伝えるか。二人一組で、一人が質問し、もう一人が最初に浮かんだ答えを返すと効果的。
2. 以降は未読（p.56〜58）。

### TIP07 スラングは使える？
- 少し効かせると、実在の人物が話した印象が強まる。ただしプロダクトはブランドの接客係。許容範囲内にとどめる。
- 母国語なら直観を信じる。母国語以外なら、ネイティブにさらりと穏やかで癖がないか確かめてもらう。
- 提供範囲が一つの文化圏でない限り、その文化圏でしか通じないスラングは使わない。
- 有害・性差別的・人種差別的なスラングは一切禁止。

## 8. 第3章 モチベーションを高めるマイクロコピー（p.57〜63）

章の内容：ベネフィットは最高のモチベーター／やる気を引き出せばユーザーは動く／ときには扉を開くだけで十分／ソーシャルプルーフは効く。

### 4大原則
1. **行動の方法ではなく、行動することの価値を伝える。**
   - ユーザーは数秒で価値があるかを判断する。言葉はシンプル、明快、説得力のあるものに。
   - 手順や方法ではなく、ユーザーが何を得るかをテーマに書く。
   - 例：「正しい財産管理のための多彩なツール」→「債務ときっぱり決別しましょう」。「中古車の新しい購入方法」→「次の車を買いましょう、この方法なら安心です」。
   - 自問する：使った人にどんな変化が起こるか。できなかった何ができるようになるか。どんな問題を解決できるか。それを伝える。
   - 自分のプロダクトについて語りたくなるが、**語るのはユーザーのことだけ**。何を与えるかではなく、彼らが何を受け取るか。
   - 法則：**文の主語を、語りかけている相手にする。**「登録手続きが迅速な支払いを実現します」→「ユーザー登録をすると、すぐに支払いができます」。
2. **ニコニコ効果、ワクワク効果。**
   - ユーモアがあると、人は自己肯定感を高め、インターフェイスを好ましく受け止め、提案を受け入れて協力的になる（ナス教授）。
   - ただし知性を問うユーモアや複雑な言葉遊びは避ける（置き去りにされる人が出る）。差別的な表現、ユーザーの苦痛や困難をネタにするのも厳禁。
   - ワクワクする気持ちは、リスクを恐れず行動する準備を整える。決断したくなる。
3. **ユーザーに敬意を払う：行動へのお誘い。**
   - CTA（行動喚起）を「行動へのお誘い（Invitation To Act）」と捉える。行動のベネフィットを分かりやすく示して扉を開き、踏み出すかは本人に決めてもらう。
   - 押しの強い手法は短期的には効いても、信頼、継続性、感情的なつながりのある関係には結びつかない。一度きりではなく、長く使い続けてもらう。
   - コツ：望ましい行動がどんな利益につながるかを説明し、誘いかける。前向きで押し付けがましくない表現。不誠実な引っ掛け手法には頼らない（TIP08 ※未読）。
4. **ソーシャルプルーフ（社会的証明）。**
   - 人は周囲の行動に合わせて決める（混んだレストランに入る、いいねが多い投稿にいいねを押す）。他の人も同じ選択をしたと分かると、不確かさが減る（続きは未読）。

**Soto への示唆：**
- 「楽しさは、画面の外に。」は原則1・2に合っている。一方で「SNSもゲームもない」は、ユーザーが得るものではなく製品の仕様の説明になっている。「ない」ではなく「何が手に入るか」を主語にする。
- 最後の呼びかけは「お誘い」の形に。押し付けず、得られるもの（発売時に最初に案内が届く）を示して、決めるのは本人に任せる。
- サイトの主な呼びかけは「先行登録（無料）」で統一されている。ただし「予約金」という別の言葉も並んでいるので、使い分けのルールを明文化する（SNSは先行登録のみ、予約金はサイト内の説明だけ）。コミュニティ感を出すなら「参加する」も候補。

### ソーシャルプルーフの種類（p.62）
- 研究では、ソーシャルプルーフでコンバージョン率が大きく上がる（チャルディーニ『影響力の正体』）。肯定的なソーシャルプルーフをボタンのすぐ近くに置くと、クリック率が上がる（ボタンは第11章）。
- 種類：
  - **数**：購入した人、利用者、閲覧者、ダウンロード数、再生時間の合計。
  - **具体性**：最近使った人の名前、よく使われる場面。人名・写真・発言の引用など、具体的なほど信頼される。
  - **他のユーザーの意見・感想・推薦**。
  - **格付け**：人気の人の起用、評価サイトの引用。
  - **公式なアワード、報道の好意的なレビュー**。
  - **ソーシャルメディア**：共有やいいねの数。
  - **他のユーザー**：すでに使っている重要な顧客のロゴや名前。

### コラム：「いいえ結構です、愚かであろうとかまいません」（p.63）
- コンファームシェイミング（マニピュリンク）：断るボタンに、ユーザーが自分を疑い、自信を失うような言葉を入れる手法。「いいえ結構です、節約したいとは思いません」など。
- 短期的にはクリックが増えるが、長期的にはブランドの評価と信頼を犠牲にする。残るのは「自分は愚かなのかと思わされた記憶」だけ。
- **ユーザーの立場に身を置き、ユーザーが自分自身を好ましく感じられる書き方をする。** 即時のコンバージョンが減っても、ロイヤル顧客は大きく増え、必要なときに戻ってきてくれる。

**Soto への示唆：**
- 先行登録者が増えたら「◯人が登録しています」を、ボタンのすぐ近くに置く候補にする。ただし**実数だけを使い、盛らない**。人数が少ないうちは、数より「具体性」（実際に登録した人の一言、名前や年代は本人の許可を取って）のほうが向いている。
- 報道・アワード・推薦は、実際にあったものだけを載せる。
- 「スマホに支配されたままでいいですか？」のように、登録しない人が自分を責めたくなる言い方は使わない。断る選択肢（配信停止、あとで）も、相手を責めない言葉で書く。

## 9. Part 2 エクスペリエンスとエンゲージメント（p.65〜）

### あらゆる言葉がオポチュニティ（好機）（p.65）
- Part 1 はボイス＆トーン（どんな語り口で話すか）。Part 2 は、実際の画面ごとにそれをどう活かすか。
- サイトのあらゆる言葉、ページ、フォームが好機。タイトル、入力欄、ボタン、厄介なエラーページまでおろそかにせず、ちょっとした意外性やワクワクする仕掛けを入れて、ユーザーに寄り添っていることを伝える。
- 章構成：4 会員登録・ログイン・パスワードの復元／5 メールマガジンの配信登録／6 お問い合わせ／7 エラーメッセージ／8 成功メッセージ／9 エンプティステート／10 プレースホルダー／11 ボタン／12 404エラー／13 待ち時間。

## 10. 第4章 会員登録、ログイン、パスワードの復元（p.66〜81、p.75・77〜79 は未読）

章の内容：優れた会員登録フォームを作る3つのヒント／ソーシャルメディアのアカウントを使う登録／登録済みユーザーのログイン画面／パスワードの復元。

### 会員登録フォーム（p.67）
- 会員登録を勧めることは、繰り返し使ってもらうよう働きかけること。そこには関係性への期待がある。
- けれどもユーザーには、登録しないもっともな理由が少なくとも2つある。
  1. **手間と不安**：空欄を埋める作業をひどく嫌う。個人情報を渡し、パスワードを考え、望まない約束や支払い義務が生じるリスクもある。
  2. **関係を結ぶのは責任を負うこと**：必要に迫られていないのに、わざわざ責任を負いたい人はいない。サイトを見るだけで平穏に暮らせるなら、登録する必然性はない。
- どのくらい避けたがるか：大いに。支払いの前に登録を強要すると放り出す。登録必須をやめて年3億ドル利益が増えた例（ジャレッド・M・スプール "The $300 Million Button"）。
- だから登録ページの言葉は、障壁と受け取られる要素を取り除き、**関係を結ぶことが望ましく、登録すれば本人に利益がある**と理解してもらうためにある。

### 語りかけのないフォームではだめ（p.68）
- 「姓・名・メール・パスワード・確認・登録」が並ぶだけのフォームは、判断材料も、離脱を引き止める働きかけもない。
- 表示するだけでは不十分。モチベーションに働きかけて完了までサポートする。対策は3つ。

### 1. タイトルを変える（p.68〜69）
- ユーザーを「ユーザー」と呼ばない。「新規ユーザー」「既存ユーザー」「登録済みユーザーはログイン」は避ける。
- 「会員登録」「アカウントの作成」など、今の状況とやるべきことが分かる言葉を使う。ただし実用一辺倒にせず、会話体で直接語りかけ、歓迎を伝える。
- 例：「はじめまして」「会員登録はこれからですか？ では、このページで正解です」「お会いできて嬉しいです」「どうぞ中へ！」「さっそく登録して、…を始めましょう」。
- ただし独創的になりすぎない。大切なのは、登録したい人に**正しいページに着いた**と伝えること。
- 工夫してよいのは**登録フォームのタイトルだけ**。ナビゲーションの「会員登録／ログイン」の文字はいじらない（ユーザーはまさにその言葉を探している）。

### 2. 登録がなぜ本人にとって望ましいかを伝える（p.69）
- 貴重な2分を使う意味を説明する。登録して初めて手に入る利益をすべて書き出し、特に重要なものを**フォームの一番上かその次に、2〜3個だけ**箇条書きにする。欲張らない。
- 例：支払いが速い、ウィッシュリスト、入力が一度で済む、注文状況の確認、限定コンテンツ、会員割引。
- 内容を検証し、本当に利益になるものを選ぶ。

### 3. 障壁を取り除く（p.70）
- 登録しない理由：①入力に時間と手間がかかる ②メールアドレスを知られてスパムに悩まされたくない ③後から支払いを請求されるかもしれない。
- これらに言及して不安を取り除く：手続きは短く簡単だとはっきり伝える。メールアドレスを他者に渡さない、大量に送らないと約束する。

### 最後に、ボタンと成功メッセージとエラーメッセージ（p.70）
- ボタンには必ず行動喚起の言葉（第11章 TIP19）。登録して正解だったと感じさせる成功メッセージ（第8章）。分かりやすく気持ちよく読めるエラー（第7章）。

### 事例（p.70〜74）
- **Nike**：「あなたのアカウントでナイキのすべてにアクセスできます」。スポーツの価値と個人の価値を、躍動感のある言葉で。
- **Life is Good**：「NEW CUSTOMERS」＋簡単だという一文＋利点3つ。オーソドックス。タイトルにもう少し遊びがあってもよい。
- **TED**：「Welcome to TED. あなたとあなたのアイデアを歓迎します」。タイトルと最初の文が連携して歓迎を伝え、吟味した利点を簡潔に。Facebook 登録の横に「許可なく投稿しません」と約束。
- **Thieve**：「Sign in to like, collect and be notified of sales.」無駄がない。ただボタンだけで、それが登録にもなると分かりにくい。
- **Society6**：アーティストを支援すること自体を利点として示す。ユーザーも同じようにアートと作り手を愛していると信じる、信頼のこもった言葉。
- **food.com**：タイトルなしで直接本題（利点）に入る。確認作業を飛ばせる。
- **B4U ペイ**：「Why sign up?」で利点3つ、最後に「登録もサービスも無料。得るものしかありません」。
- **PayPal**：「会員登録は無料です！」とタイトルで金銭面の障壁を除く。登録で生活がどう変わるかを説明。
- **Medium**：登録者だけの利点を並べ、楽しさが広がると伝える。

### コラム（再掲）：サインイン vs. ログイン
- 「サインアップ」と「サインイン」は並べない。サインアップと組むなら「ログイン」。一度選んだ言葉は全体で一貫させる。

### ソーシャルメディアのアカウントを使う登録（p.76）
- 入力の手間が省け、運営側も情報を得られる。ただしユーザーが個人情報を渡すことに変わりはない。ページ上部で登録の価値を伝えるのはやはり必要。
- 少なくとも一つは書き添える：
  1. **ユーザーの情報を一切公開しないと約束する**（登録ボタンの隣に）。
  2. ソーシャル経由が最も速く簡単だと伝える。
  3. 個人情報が大切だと認識し、守るために最善を尽くすと伝える。
- ソーシャル経由の登録をためらう唯一の理由は、個人情報を守る約束がないこと（著者の見解）。

**Soto への示唆（今のサイトのフォームを見て）：**
- 良い点：入力はメールアドレスだけで、手間の障壁は小さい。「登録は無料です。購入の確定やお支払いは発生しません。メールは発売と先行体験のお知らせ、月1回の開発レターにだけ使い、いつでも止められます」という、障壁①〜③への答えはすでに書いてある。
- 直したい点：その答えが「登録について」の折りたたみの中に隠れている。本の通りなら、**ボタンのすぐ近くに一行で**見せたい（例：「無料です。お支払いは発生しません。メールは月1回まで、いつでも止められます。」※回数は実際の運用に合わせて決める）。
- フォームの上に、登録して手に入るものを2〜3個だけ置く候補：発売の案内が最初に届く／先行体験に参加できる（希望者のみ）／No.300 まで本体に番号を刻める。※どれも今サイトに書いてある内容から選ぶ。新しい約束は作らない。
- 「プライバシーポリシーに同意したものとします」は事務的。必要な一文だが、主役にせず、約束（他者に渡さない・送りすぎない）を先に書く。
- ナビの「先行登録」は変えない。工夫するのはフォームの見出しだけ。A/B の案で、ナビが「先行体験」、ボタンが「先行体験に登録」になるものがあるので、どれを残すか決めたら全体をその言葉で統一する。
- ソーシャルログインは今は使っていないので、p.76 は将来アプリやアカウントを作るときの参考。

### パスワードの復元（p.80〜81）
- パスワードを忘れた人は、新しいパスワードを手に入れること以外は何も考えられない。だから気の利いた表現は似合わない。凝りすぎず、**短く、シンプルに、実用的に**。
- **Tumblr**：メール欄と「キャンセル」「パスワードのリセット」だけ。やり方を皆が知っているなら余計な言葉は要らない。
- **Upserve**：「リンクを送ります。それを使えば安全にパスワードを変更できます」。分かるか心配なら短い説明を一文。
- 少しだけ気持ちを和らげる言い方をすると、さらに楽になる。
  - **OkCupid**：「Lost your password? We got you.（了解です）」。本人だと信じている言い方で安心させる。
  - **TeuxDeux**：「パスワードをお忘れですか？ 誰にでもあることです」→ボタン「ヘルプを依頼」→「今助けに行きます！ メールの指示に従ってください」→成功時「パスワードは更新されました。さあ、戻りましょう！」。共感して、救いの手を差し伸べる。

**Soto への示唆：** 今のサイトにログインやパスワードはない。将来、アプリや会員ページを作るときは、困っている場面なので遊びは一言まで。「誰にでもあることです」のような、責めない一言はブランドに合う。

## 11. 第5章 メールマガジンの配信登録（p.82〜92）

章の内容：配信登録を促す3種のCTA／お誘いの言葉に説得力を持たせる3ステップ。

### なぜ配信登録をするべきか（p.83）
- ブランド側には明らか：長く価値ある情報を届け、存在を忘れられず、親しみと信頼の関係を育てられる。新製品の案内は売上につながる。
- 問題は、ユーザーは乗り気でないこと。配信登録はスパムの元凶、望まない情報が山ほど来ると思っている。そのリスクを越えてもらうには、本当に説得力のある理由が要る。
- 表示方法：訪問時やスクロール時のポップアップ、会員登録フォームのチェックボックス、フッターやサイドバーのフォーム。全部使ってもよい（TIP10）。

### お誘いメッセージの3つの型（p.83〜85）
1. **凡庸型**：使い古しの定型文（「メールマガジンの配信登録を！」「このメーリングリストにご参加ください」）。デザインが美しくても台無し。毎日似たポップアップを見ているので、どれも同じに見える。メールアドレスを簡単に知らせたくないのに、こんな文で差し出す気になるか。
2. **新着情報アピール型**：「最新情報を届けます」「誰よりも早く」「仲間になりましょう」「チャンスを逃さずに！」。どれも、基本的に何も言っていないのと同じ。サイトを見ている人は主な情報をもう知っていて、届く内容も予想がつく。似たお誘いを見すぎて、定期購読のメリットを疑っている。伝えるべきは**情報の新しさではなく、メールが何をもたらすか**。
3. **説得型**：他のセールスと同じ。メールアドレスと引き換えに見合う理由を示す。誰にでも書ける漠然とした理由は通用しない。受信トレイに届くことで何が手に入るかを伝え、**教えたくない気持ちより得られる価値が大きい**と思ってもらう。ボイス＆トーンを設計していれば、ユーザーが何を得たいかは分かるはず。

### TIP10 すみません、どこかでお会いしましたか？（p.85）
- 初めての訪問ですぐポップアップを出すと、見知らぬ人が不意に距離を縮めてくる印象になる。まだ信頼がないので、登録する理由がない。
- 提供できるものを少し理解してもらってから勧める：訪問の1分後、記事を半分読んだとき、別の記事を開いたとき、フッターまでスクロールしたとき。**サイトの概要が分かるまで待つ。**

### 配信登録を促す方法（p.86〜87）
1. **タイトルを変える**：「メールマガジンの配信登録」「メーリングリストに参加」は、差し出せるものではなく、頼みごと（操作）。メールが提供する価値と、それで生活がどう良くなるかを先に示すのが良いタイトル。例（人付き合いのメルマガ）：「人付き合いを成功させるまでの道のりは険しい、と教わりましたか？ それを、心躍る冒険にしてしまいましょう！」
2. **配信登録したら何が得られるかを伝える**：タイトルで面白さが伝わった時が勧めどき。「最新情報」「耳寄り情報」「特別オファー」では不十分。ブランドならではの、具体的で実際的な価値を。ユーザーが「はい、これこそ私が手に入れたい情報です。喜んで受け取ります」と言える利点を示す。例：「今すぐ配信登録をすれば、毎週こんな情報がお手元に：限定コンテンツ／専門家の独占インタビュー／おすすめスポット」。
3. **障壁を取り除く**：一番の理由はスパム。申し込んでいないメールだけでなく、**登録したメールでも数が多すぎればスパム**。
   - a. 配信頻度は高くないこと、頻度を明示して約束する。
   - b. メールアドレスは確実に守り、個人情報を厳重に扱うと約束する。
- 最後に、ボタン（第11章）、印象的な成功メッセージで最初の配信に期待させる（第8章）、入力ミスのエラー（第7章）も仕上げる。

### TIP11 無料コンテンツ！ 今すぐダウンロード！（p.88）
- 無料コンテンツでも書き方は同じ：①独自の価値が伝わるタイトル ②読めば暮らしがどう良くなるか ③個人情報を守り、外に出さないと約束。

### コラム：読んでくれるか心配ですか？ 大丈夫です（p.88）
- ContentVerve のマイケル・アーガルド "How to Write High-Converting Sign-Up Form Copy"。
- 「コンテントバーブからの最新情報をゲット」→「最新情報をゲット：ケーススタディ＆テスト結果／ハウツー動画＆記事／オピニオンリーダーを迎えるポッドキャスト」。変えたのは短い箇条書きだけ。登録率が83.75%増加。

### TIP12 事業や商品の情報だけを扱うなら（p.89）
- 販売チャネルとして割引や特典だけを送るなら、まず読み物として充実させる（専門家の提案、テーマ別のリスト、インタビュー、サクセスストーリー）。
- 時間や予算がなければ、せめて登録フォームに特色を：「割引価格で購入できます」→「〈ブランド名〉の華麗な夏の新作コレクションを割引価格で」。「最新情報」→「サイトに載るより前に、最新の求人情報が受け取れます」。
- Walmart：「Sign up for Savings（会員登録で上手に節約）」。

### 事例（p.90〜92）
- **GoodUI**：「メールマガジン」という言葉すら出ない。「私たちのテスト結果から学んでください」。調査はこちらで進め、あなたは結果を受け取るだけ。ボタンも利点の言葉（「はい、新しいデザインパターンとテスト結果を知らせてください」）。最後に「いつでも退会できます。お送りするのは週に2通まで」。
- **Barking up the Wrong Tree**：ソーシャルプルーフ（掲載実績＋購読者32万人超）、得る価値（輝かしい人生）、正確な頻度（週に一度）、スパムなしの約束。
- **YFS Magazine**：価値（一流の起業家の助言で素晴らしいブランドを）、頻度（週1）、ボタン下で「スパムなし、約束します！」。
- **The North Face**：「HIT THE GROUND RUNNING（今すぐダッシュ）」。ごく短い言葉が、スポーツを愛する人に響く。
- **Marie Forleo（現行）**：読者の声「定期購読して、もっと頻繁に送ってほしいと思ったことなど一度もなかった」→「MF Insider になる。受信トレイを覗くことが楽しみになります」→ボタン「よろしくお願いします！」。
- 6例中5例が「メールマガジン」という言葉を使っていない。この言葉が出ると及び腰になる人がいる。避けるなら、別の言い方で中身を確実に伝える。
- **欄外であっても例外ではない**：フッターやサイドバーの小さなフォームも、「メールマガジンの配信登録」だけでは不足。限られた言葉で利点と頻度を伝える。例 **Sugru**：「月に一度お届けする多彩なアイデアやインスピレーションを」＋「AWESOME!」のイラスト。
- **Marie Forleo（旧版、著者が一番と言う作例）**：「あなたは、あなたが愛する仕事と人生にふさわしい存在です。私たちがお手伝いします。」受賞実績のある動画を毎週。なぜ優れているか：
  1. タイトルで極めて魅力的な価値を余すところなく提示。
  2. 配信登録という行動ではなく、その先の価値に言及。本人やビジネスの説明にはほとんど触れず、ひたすらユーザー中心。
  3. 配信頻度を明記（毎週）。
  4. ソーシャルプルーフ（受賞実績）。
  5. あらゆる言葉に人柄が感じられる。カリスマなのに同じ仲間として語りかけ、高い目標を掲げつつ今のあなたへの思いやりと共感を忘れない。

**Soto への示唆：**
- Soto の先行登録は、実質「発売のお知らせ＋月1回の開発レター」の配信登録。だから第5章がそのまま当てはまる。
- 「月1回の開発レター」はロードマップの表と、折りたたみの中にしかない。**頻度を明示する**のは本が繰り返し勧める一番の障壁対策なので、フォームの近くに出す価値がある。
- 「開発レター」は新着情報アピール型に近い。何が届くかを具体的に書く候補（実際に送る予定の内容だけにする。未定なら先に決める）：試作機の写真と、うまくいかなかったこと／中国の工場で見たもの／先行体験の募集の案内、など。
- 「最初にお知らせします」「誰よりも早く」は新着情報アピール型。「発売のお知らせ」だけでなく、受け取ることで何が手に入るか（外の時間の過ごし方のヒント、作り手の裏側）を言えるとよい。
- コラム（約70本）にはフォームがない。TIP10 の通り、記事を読み終えたところ（末尾）に小さな案内を置くのは理にかなう。最初からポップアップは出さない（ブランドの「静けさ」にも反する）。
- 「メールマガジン」という言葉は今も使っていない。良い状態なので、そのまま避ける。
- Marie Forleo 旧版の型（あなたは〜にふさわしい／私たちが手伝う／届く頻度／具体的な3つ）は、Soto の最後の呼びかけを書くときの手本になる。ただし誇張や、実績のない「受賞」などは書かない。

## 12. 第6章 お問い合わせ（p.94〜103）

章の内容：お問い合わせページはなぜ重要か／ブランドを知りたい顧客のためのページ／サポートのためのページ。

### どのようなご用件ですか？（p.95〜96）
- デジタルプロダクトは組織のバーチャル版。お問い合わせページは顧客サービスそのもので、知りたいとき（見込み顧客）と助けが要るとき（既存顧客）に頼る場所。だから**他のページ以上に温かく迎える**サービス志向のページに。
- 「名前・メール・電話・コメント・送信」だけのフォームは、体裁は整っていても、本当に問い合わせを待っているのか分からない。担当者が笑顔で「何かお困りですか？」と迎えるのではなく、無表情で突っ立っている印象。
- 「お客様の声をお待ちしております」「どんな質問にもお答えします」「弊社は顧客満足に投資しております」「翌営業日中にご返答いたします」「今後もサービス向上に努めてまいります」も、誠意を感じない定型文。ユーザーは「サービス向上」より、今すぐ問題を解決し、自分個人に宛てて話してほしい。
- まず自問する：ユーザーは**どんな状況で**問い合わせが必要になったか。**何を達成したいか**。状況ごとにメッセージを作る。

### 1. 見込み顧客のためのお問い合わせページ（p.96〜97）
- ここまで来てくれたことで安心してアクセルを緩めない。「問い合わせをするのが一番だ、この選択こそ大正解だ」という印象を強める。
- 会員登録・配信登録と同じく、ありきたりなタイトルを価値を伝えるタイトルに。コンタクトを取ることでどんな利点があるかを伝える。スタイルガイドがあれば分かるはず。なければ、これを機に考える。
- 事例：
  - **Netcraft**：「5つのもっともな理由：お手伝いが私たちの喜び／あなたのニーズを知りたい／理想のプロダクトへの最速の方法／ミーティングにはクッキー／私たちは皆いい人ですよ(^^)」。1〜2は信頼、3は価値、4〜5はブランドの楽しませる精神。
  - **Epipheo**：「無料相談をご利用ください。文字通り相談です。動画が売れればいいとは考えていません。合わなければ誰よりも先に伝えます」。誠実さと頼もしさが伝わる。ただし長すぎると離脱するので2〜3行が賢明かも（著者）。

### 2. 顧客サポートのためのお問い合わせページ（p.97〜98）
- 困っているときこそ、サービス志向を最大限に発揮するチャンス。あなたのためにここにいる、力になれたら嬉しいと伝え、信頼に誠実に応える。
  1. **どんな問い合わせにも、喜んで誠意を尽くして応じる姿勢を伝える。**うまくいかないときこそサービスの質が問われる。いい加減な言葉は通用しない。
  2. **厳密な言い方をする。**「あらゆる質問や提案」ではなく、製品やサービスに直結する表現で。何に関する質問か、どんな分野の提案か。
  3. **フォームにも取り除くべき障壁がある。**自分の問い合わせが読まれないかもしれない、返事が来る頃には忘れているかもしれない、という不安。**すべて読むと約束し、返答までの時間を伝える。**
- 事例：
  - **IKEA**：問い合わせの理由をいくつか挙げ、「すぐに簡単に解決します。そうしたら、新しいソファに座って寛いでください」。ソファこそ、IKEA に来たきっかけ。
  - **Marie Forleo**：「質問も、コメントも、あふれるような愛のメッセージも」。すべて読み、48営業時間以内に返事するよう努める。営業時間も明記。「返事が届かなければ、私たちが受け取っていないということなので、もう一度送ってください」。どこに送られ、誰に読まれ、いつ返事が来るかの不安に答えている。
  - **Oh Happy Day**：「お便り待っています。質問？ 返品？ あなたのネコの楽しい話？」「2営業日以内にお返事します（大抵は早めです！）」。くすっと笑える一言。ただ「質問がありますか？」はもっと具体的に、商品に結びつけるとよい（「当店のカラーコンフェッティについて、何かご質問ですか？」「バルーンとナプキンの色が合わずにお困りですか？」「まだ取り扱っていない素敵なパーティー用品があれば教えてくれますか？」）。
  - **JetBlue**：「何でもお手伝いします」＋目的別のボタン（質問／提案／心配事／お褒めの言葉）。顧客グループごとに別のフォームへ誘導。
  - **NPR**：同じ仕組みで、目的ごとのボタン。
  - **InVision**：「私たちはいつもここにいます」と約束したうえで、技術的な問題はまずヘルプセンターへ。すぐ下にフォームもある。
- **FAQ やオンラインヘルプ**は歓迎されるが、担当者が直接対応せずに済ませようとしている印象を与えることもある。誘導する前に、問い合わせは大歓迎であることと、FAQ が最も速く解決する方法であることを強調する。

### TIP13 ジョークは脇に（p.98）
- 問い合わせる人は、不満や怒りを抱えているか、途方に暮れているかもしれない。ジョークを入れたら、不満を抱く人の身になって読み返し、怒りが増す部分がないか確かめる。お問い合わせページでは安全策を選ぶ。

### TIP14 問い合わせを、内容または緊急度で分類する（p.103）
- 分類項目を出すのは良い方法。ただし、頭の中の専門用語をユーザーの言葉に置き換える。自分の視点ではなく、ユーザーの視点から。
  - 注文済み商品→マイオーダー／請求書関係→支払いに関する質問／システムエラー→サイト内で発生した問題／一般→その他の問い合わせ。
- **Men with Pens**：「私たちの公式サイトをデザインしてください」「挨拶、お礼、お褒めの言葉を伝えたいです」「ちょっとした間違いを見つけたのでお知らせします」「やや複雑な内容です。メッセージで詳しく説明します」など、ユーザーの一人称で選択肢を書く。
- **Buffer**：緊急度を選ぶ欄。「ご留意ください（お知らせだけ）／当面は自分で対処できますが、どうか直してください／行き詰まりました、何をやってもうまくいきません／頭を抱えて苦しんでいます／緊急です、危機的状況です」。

**Soto への示唆（今の contact ページを見て）：**
- 良い点：用件の例を具体的に挙げ、「3営業日以内に、メールでお返事します」と返答時間を約束し、「お返事のためだけに使います」と個人情報の約束もある。本の勧めをすでにかなり満たしている。
- 足せる点：
  - 「**すべて読みます**」の一言（本が挙げる障壁③への答え）。そして Marie Forleo のように「3営業日たっても返事がなければ、届いていない可能性があるので、もう一度送ってください」。実際の運用で守れる範囲で。
  - 用件の選択肢は今「製品について／提携店として／学校・企業での導入／取材・お仕事のご相談／その他」。Men with Pens のように、ユーザーの一人称で書く手もある（例：「製品について聞きたい」「お店として提携したい」）。ただし今のままでも分かりやすいので、優先度は低い。
  - 見出しの「お問い合わせ」は、ナビやフッターの言葉としては変えない。ページ内の最初の一文で、温かく迎える（例：「どんなことでも、気軽に聞いてください。」のような言い方。ブランドの関係性を決めてから書く）。
- お問い合わせではジョークを使わない（TIP13）。Soto の静かなトーンにも合う。
- 発売後のサポート（壊れた、LINE が届かない等）では、FAQ に誘導する前に「問い合わせは歓迎です。急ぎならこちらが一番早いです」と添える。緊急度の選択肢（Buffer 型）は、通話やSMSが使えない＝連絡手段を失っている人もいるので、発売後に検討する価値がある。

## 13. 第7章 エラーメッセージ（p.104〜110、途中まで）

章の内容：エラーメッセージの3つの役割／二段構えの理想的なエラーメッセージ／エラーメッセージのボイス＆トーン／あらゆるサイトに必要なエラーメッセージ。

### 当惑しているユーザーのための応急手当（p.105）
- エラーメッセージは、できれば読んでほしくない唯一のテキスト。エラーは起こさないのが一番（第17章）。それでも見せることは多いので、慎重に言葉を選び、確実に救い出す。
- エラーは操作を中断させ、前に進むことを阻む。分かりにくかったり、追い詰めるような言い方だと、操作を投げ出してしまう。
- **3つの役割：**
  1. 問題が起きた事実と、その性質を、簡潔に分かりやすく説明する。
  2. 解決策を示し、すぐに元に戻って操作を完了できるようにする。
  3. 操作の遅れを、できるだけ好ましい経験に変える。
- 文面は分かりやすく、実際的に、シンプルに。**遊び心が似合う場面ではない**。ただし冷静でいろという意味ではない。不快な思いをさせているからこそ、ごまかしのない人間的な言葉で不快感を和らげる。ユーザーが目の前にいたら、優秀な顧客サービス担当者ならどう声をかけるか。

### 二段構えの理想的なエラーメッセージ（p.106）
1. 問題の性質を伝え、何がエラーなのかをできるだけ正確に説明する。
2. 解決して操作を続ける方法について、建設的なアドバイスをする。その時点で解決できない場合は、どんなサポートを誰が提供できるかを伝える。
- 例外：会員登録やログインのよくあるエラー（パスワードが不適当、ユーザー名が既に存在など）は、どちらか一方を省いてよい場合もある。皆よく経験していて、性質も解決法も知っているから。

### TIP15 適切なエラーメッセージを書くために確認する4つのこと（p.106）
1. エラーが起きたとき、ユーザーは何をしようとしていたか。
2. システムはなぜエラーを返したか。
3. ユーザーが何をすれば操作を続けて完了できるか。
4. 解決策がない場合、別の選択肢を提供できるか（サポートに問い合わせるなど）。

### コラム：汎用性が高いと、有用性は低い（p.106）
- 予算や日程の都合で、いくつもの状況に一つのエラーで対応すると、何が問題か明確にできず、解決策も示せない。魔法の杖はない。個別の状況に対応してこそ有用。
- 汎用のメッセージしか用意できないなら、せめてできるだけフレンドリーな言い方を。

### エラーメッセージのボイス＆トーン：人間らしく、サービス志向で（p.107〜108）
- 第2章の会話体を、ぜひ実践すべき重要な局面がエラー。警告のような文だと最後まで読まれない。
1. **堅苦しい、高圧的、指示するような言い方を避ける。**法律家が申し渡すような言い方をしない。悪い例：「空欄を埋めてください」「これは必須項目です」「手続きを進められません、以下の欄が正しく入力されていません」「携帯電話番号を入力することが必要です」「お客様、この操作は禁止されています」。
2. **「エラー」「失敗」という言葉を使わない。**悪い例：「エラー！ 正しい情報を入力してください」「入力内容にエラーがあります」「操作は失敗です」。
3. **技術用語や専門用語を避ける。**バリデーション、ベリフィケーション、法的、証明、サポートされていないアクション、システム、許可、エラー番号など。悪い例：「致命的なエラー：…例外が発生しました」「無効なログイン認証情報」「不正なメールアドレス」「エラー5647GV」。
- 威圧感のある言葉はやめ、責めず、楽しい会話のように、シンプルに問題を説明してから解決策を示す。
- **何がいけないかではなく、どうすればよいかを伝える。**
  - 「電話番号が無効です」→「電話番号は10桁で入力してください」
  - 「この便は予約できません」→「ダブリンへの直行便は8月のみ利用できます」

### TIP16 エラーメッセージにユーモアはあり？ なし？（p.108）
- ブランドのボイス＆トーン次第。軽やかなブランドなら笑顔にする文もよい。ただし何より分かりやすく実用的で、必ず解決策を示すこと。凝りすぎると理解されないし、問題を小さく見せたがっていると思われる。ユーモアは少量に。
- OurHome：年齢に130と入れると「わぁ、ずいぶん高齢ですね！ 史上最高齢記録は122歳です。本当ならギネスに申請してください」。ふざけていて長いが、笑顔にはなる。

### 事例（p.109〜110）
- 同じ内容でも：「30日以上の予約はできません」（否定、何ができないか）と、Hipmunk「そろそろ移り住みませんか？ 30日が最長です」（肯定、何日が最長か、茶目っ気）。遊び心はブランドボイスに合うなら有効だが、つねに必要ではない。伝統的なブランドなら「予約は最長30日まで可能です」で十分。
- 「ユーザー名またはパスワードが間違っています」の言い換え：
  - **Pinterest**：「おや？ メールアドレスが違うか、パスワードが違います。リセットしますか？」
  - **Mailchimp**：「すみません、そのユーザー名のアカウントが見つかりません。ユーザー名の復元をご希望ですか？」
  - **Tesco**：「残念ながら、これらの詳細情報を認識できません。もう一度お試しください。」
- **Vimeo**：登録済みのメールに「やあ、このメールアドレスはもう知っているよ！ ログインしたい？」。**BBC**：「このメールアドレスは既に登録済みのようです。ログインをお望みですか？」
- **Google**：ユーザー名にピリオドが連続すると「句読点がお好きなんですね！ でも残念です、ユーザー名にピリオドは連続して使えません」。限られた状況だけに通じるユーモア。
- **Facebook**：「すみません、混乱しています。ページを再読み込みするか、ブラウザを閉じて開き直してください」。人間味のある一言＋2つの解決策。

**Soto への示唆（今のサイトの文言を見て）：**
- 「メールアドレスの形を確認してください（例：you@example.com）。」→ 「エラー」「不正」を使わず、どうすればよいかを示している。本の基準に合っている。
- 「登録できませんでした。時間をおいて、もう一度お試しください。」「…通信状態を確かめて、もう一度お試しください。」→ 原因を分けて解決策を出している点は良い。足すなら、TIP15 の④（解決できないときの別の道）：「何度試しても登録できないときは、hello@sotophone.jp に一言ください。こちらで登録します。」※実際にそう運用できる場合だけ。
- まだ用意していない可能性がある状況：**すでに登録済みのメールアドレス**で登録したとき。Vimeo / BBC のように「このメールアドレスは、もう登録してくださっています。ありがとうございます。」と、責めずに安心させる一言にする（どう表示されているか、実装を確認する必要あり）。
- Soto のエラーではユーモアは使わない。静かで丁寧なトーンのまま、短く、解決策を一つ添える。

## 14. 第8章 成功メッセージ（p.114〜121）

章の内容：成功メッセージの3つの目的／良質な成功メッセージを作る4つの要素。

### 終わり良ければ全てよし（p.115）
- ナス教授：人はコンピュータが相手だと承知していても、社会規範に則った対応を期待する（褒めるべきときは褒め、間違ったら助け舟を出す）。
- 一つの行動が完了したときの成功メッセージは、ユーザーが最も待ち望む反応の一つ。
- 成功メッセージで締めくくるべき行動：会員登録・参加申込み、購入・注文、配信登録、退会、無料ガイドのダウンロード、お問い合わせの送信、ファイルのアップロード、メールアドレスの確認、無料トライアル、パスワードの復元など。

### 成功メッセージの3つの目的（p.115）
1. **確信を提供する**：行動が間違いなく完了し、すべて順調だと伝える。
2. **指示を与える**：次の任意または必須の操作を伝える。
3. **気持ちを通わせる**：一連の作業を締めくくる最後の一言。うまく伝われば達成感と爽快感を味わい、晴れ晴れとした気持ちになる。行動に豊かな意味が加われば、ブランドに好ましい印象を抱き、体験に満足する。

### いつも全部は要らない（p.116）
- メール送信や保存のような頻繁で簡単な操作は、チェックマークを数秒出すだけ、ごく短い実用本位の文で十分。ユーザーにとって重要な行動には、重要度に応じた丁寧な成功メッセージを。
- 悪い例：「取引は正常に完了しました」「登録が完了しました」「ご注文を確かに受け付けました」「あなたのメールアドレスを確認しました」。「Xは正しく完了しました」は目的①だけで、事務的で無表情。避けるか、少なくとも残り2つの目的のどちらかを果たす言葉を添える。

### 良質な成功メッセージの4つの要素（少なくとも1〜2つ、できればすべて）（p.116〜118）
1. **やり終えた行動ではなく、ユーザー自身のストーリーを語る／ユーザーに語りかける。**操作ではなく、やり遂げた人を主役に。OkCupid は「写真は正しくアップロードされました」と言わず、写真ごとに「最高」「大好き」「これいいね」「イエスイエスイエス」「みんなあなたに恋しちゃう」。
2. **操作が実際に完了したことを、分かりやすく示す。**定型文は要らない。分かりやすく、少し工夫を。OkCupid はアップロードした写真を実際に画面に出す。The Outline の配信登録完了は「TTYS.（またあとで）」だけ。完了の確認と、これからの話題への期待の2役。ただし世界に向けるなら頭字語は避ける。
3. **行動がもたらす、より深い意味に言及する。**どんな価値を受け取るか、どんな効果があり、どれだけ重要かを簡潔に。配信登録なら「最新号をすぐ受信ボックスに届けるので、待たずに読めます」。レジャー用品の購入ならワクワク気分を共有。お問い合わせなら、信頼に必ず応えるつもりで、すでに対応を進めていると伝える。
   - WordPress：「成功！ WordPress はインストールされました。もう少し作業があると思っていましたか？ 期待外れですみません。」ユーモアと同時に、シンプルさという製品コンセプトがここでも実現していると分かる。
4. **次のステップを伝え、行動を促す。**
   - 今どんな処理がどう進んでいるか（回答までの時間、配送予定日、サービス開始日、再起動が必要か）。
   - メールを送ったなら、受信トレイを確認するよう促す。
   - 次にしてほしい行動（利用開始のページ、アプリのダウンロード、SNSでのフォロー）。
   - それ以上の操作がないなら、商品紹介やブログなど、興味のあるコンテンツに戻ってもらう。
   - 参考：ターリア・ウルフ "Use these 7 hacks on your thank you page to boost retention"。

### 事例（p.119〜121）
- **Marie Forleo**（配信登録完了「YOU'RE THE BEST!」）：上の5つをすべて実践。①行動ではなく本人とフォレオの関係について語る ②完了を伝える（専門用語なし） ③本人を主役に、素晴らしい絆ができたと伝える ④心のこもった言葉で受信トレイの確認を促す（1通目を読んでほしい） ⑤エレガントにSNSでのフォローを誘う。署名入り。※写真がぶれて本文の細部は読めず。
- **Epipheo**：「連絡してくれてありがとう！ あなたのリクエストを、私たちの動画制作のエキスパートたちに伝えました」。担当者3人を**名前と写真付き**で紹介し、信頼感を高める。最後に次のステップ（Facebook グループへの参加）。
- **Wix**：「手伝ってくれてありがとう。あなたのフィードバックは機能の改善に役立ちます」。行動が大切な意味を持つと告げる。感謝のイラスト。
- **Rounds**：「よくできました！ さあ、友達を増やしましょう…次のステップです！」。誰にでも同じ褒め言葉でも、人は気分が良くなり、そのインターフェイスを好ましく思う（ナス教授）。難しく考えず、どんどん褒める。
- **Envato**：セキュリティチェック完了で「あなたはあなた。イェイ！ アカウントの安全性をキープし、私たちに協力してくれて、どうもありがとう」。短く意外性のある言葉＋協力関係が成立したこと＋それが本人の利益になること。

**Soto への示唆（今の登録完了カードを見て）：**
- 今のカードはかなり良い：完了の確認、先行登録券（番号のきっぷ）で完了を目に見える形で示す（要素②）、番号の特典、次に起きること（開発レターと発売のお知らせが届く）、送り先アドレスと「直す」、友だちに教えるボタン（要素④）。3つの目的のうち①②はほぼ満たしている。
- 弱いのは見出し「ご登録いただき、ありがとうございます。」。本の悪い例「登録が完了しました」に近い定型文で、チェックリスト6番（誰もが使う定型文）にも当たる。要素①（ユーザーが主役）と③（行動の深い意味）がまだ足りない。
  - 方向性の例（決定ではなく、関係性・人格を決めてから書く）：「外の時間を、取り戻す一歩目ですね。」「No.◯◯ として、一緒に作っていきます。」のように、登録した人が何を始めたのかを語る。
  - ただし「すごい」「最高」のような大げさな褒め言葉は、Soto の静かな人格に合わない。褒めるなら落ち着いた言い方で。
- 要素④：開発レターが届くことは書いてある。最初のメールが実際にすぐ届くなら「受信トレイ（届かなければ迷惑メールも）を見てください」を足せる。届かないなら書かない。
- お問い合わせの送信完了「送信しました。ありがとうございます。」は要素①③④が無い。例：「受け取りました。3営業日以内に、◯◯（担当者の名前）からお返事します。」Epipheo のように、返事する人の名前があると信頼感が増す（実際に返事する人の名前だけ）。
- thanks.html など、他の完了画面も同じ基準で見直す対象。

## 15. 第9章 エンプティステート（p.122〜135）

章の内容：行き止まりのページを開かれた扉に変える方法／機能を使い始める前のエンプティステート／カートが空で注文履歴もない状態／検索結果画面。

### ここには表示する情報がありません、移動しますか？（p.123）
- 言葉には、経験すべきことが何もないように見えるときに、一つの経験を丸ごと作り出す力さえある。エンプティステートはその代表例。
- 定義：表示すべき情報が何もない状態。初めて使うときによく出るが、検索結果がゼロのときなど、操作の結果としても出る。
- 空っぽのままだと「何もない」という事実しか伝わらない。何があればよかったか、ここで何が得られたはずか、状況を動かすために何ができるかを伝えられない。
  - まだ使っていない機能なら、利点を伝えて使ってみるよう勧めるチャンス。
  - カートが空なら、購入を勧めるチャンス。
  - 検索結果がゼロなら、手ぶらで帰さず、他の選択肢を示す。
- この画面は、良質なサービスを提供し、次の行動を指し示し、本来の目的に立ち返ってもらう役割を果たせる。

### 1. 機能を使い始める前のエンプティステート（p.124〜127）
- アプリの77%は、ダウンロードから3日以内に削除される（ディナ・チェイフェッツ "Why empty states deserve more design time"、InVision ブログ）。全部がエンプティステートのせいではないが、第一印象で重要な役割を担う。
- 登録したら、カートが空、ウィッシュリストが空、履歴なし、お気に入りなし、メッセージなし、友達なし。多くの画面は空白に短い一文だけ（「まだ何も実行されていません(._.)」）。もったいない。このプロダクトは大して機能がなく、生活に変化はもたらされないと思われてしまう。
- 「何もない」ではなく、ここはどんな画面になり得るか、ここで何ができるかを伝える。機能と、それがどう役立つかを明らかにする。必要なら手順も（図解が理想）、適切なリンクも。
- 事例：
  - **Facebook**：「フェイスブックへようこそ。まずは友達を追加しましょう。友達になった人の動画、写真、投稿などが見られるようになります」＋ボタン「次へ」。意味を限定しない「次へ」のほうが人を動かしやすいのだろう（テストの結果か）。
  - **OkCupid**（受信トレイが空）：「まだここには誰もいません！ さっそく出かけて、話し相手を見つけましょう」＋可愛いイラスト。著者ならパートナー候補一覧へのショートカットボタンも足す。
  - **Tumblr**：「通知なし」と言わず「投稿を終えたらこのタブをチェックしましょう。いいね、リブログ、新規フォロワーなどが確認できます」。足りないものではなく、これから得られるものを伝える。
  - **Amazon Photos**：「まだアルバムは作成していません。アルバムを作って、写真を整理し共有しましょう」＋「新しいアルバムを作る」。
  - **Todoist**：「今日がどんな一日か、隅々まで見渡しましょう。本日のタスクはすべて、ここに表示されます」＋「タスクを追加する」。イラストは価値を象徴、ボタンは単刀直入。
  - **Monday.com**：「ゴミ箱は空です。削除された情報は30日間保管します。気持ちが変わるかもしれませんから」「アーカイブは空です。使わないボードは、必要になるまでここに保存されます」「タグはまだありません。チームのタグをここで一覧し管理できます」。機能と活用法を手際よく伝える。
  - **Canva**：「きっと素敵なデザインが完成します。あなたのデザインはここに表示されます。上の検索バーから始めましょう」。

### 2. カートと注文履歴のエンプティステート（p.128〜132）
- 空のカートを見る状況はさまざま（間違って入れたかも、入れたか分からない、削除して空になった）。
- 「カートは空です」だけではスペースの無駄。購買意欲を刺激するために使う：
  1. カートが空であることを分かりやすく伝える。
  2. 商品への興味を湧き上がらせる説得力のあるセールスコピーを。楽しませ、身を乗り出させる言葉。言葉とグラフィックを組み合わせるとさらに効果的。
  3. ユーザーが特に興味を示しそうなアイテムを紹介する（特別オファー、人気商品、新作）。
  4. ソーシャルプルーフも有効（「今週の売上ナンバー1」「今、他のお客様が最も注目しているアイテム」＋写真＋購入リンク）。他のショップや商品の興味深い統計で膳立てしてから売り場へ誘導する手も。
- お勧め品の写真を出すときは、カートに入っているように見えないよう注意。目的は購買意欲を高めることで、混乱させることではない。
- 例（チョコレート店）：「あなたのショッピングバッグにはまだチョコレートが入っていません。けれども私たちのショコラティエは…新しいコレクションが到着しました。一度食べたら虜になるはず。」＋「新しいフレーバーを探す」／「まだチョコレートが入っていません(-_-) よくわかります、選ぶのは大変ですよね。そんなあなたには：」＋「人気のフレーバーを見る」。
- 美容健康ショップは空だというメッセージさえなく、白さが眩しいくらい。→「まだ商品が入っていませんが、お買い得品を多数用意しています。いくつか紹介しましょう。」＋商品写真。
- **注文履歴**が空のときも「注文履歴はありません」だけではチャンスを逃す。例：「まだご注文がありません。でも、私たちがお届けする季節のフルーツは絶品ですよ」＋「本日の採れたてフルーツを見る」。
- 事例：
  - **Belle and Sue**：「ショッピングカートは空っぽで放置され、しょんぼりしています。商品を入れて、元気付けてあげましょう」＋「ショッピングを続ける」「注目のアイテムは？」。
  - **Busted Tees**：「カートは空です。あなたにぴったりのアイテムを見つけましょう！ 本日の特価品、新製品、お楽しみ情報は要チェック」（3つのページへ）。
  - **American Eagle**：「ショッピングバッグは空です… 新作コレクションをチェックするなら今！」＋新着3リンク。
  - **Book Depository**：「買い物かごは空です。本を探すお手伝いをしましょうか？ 1,900万冊以上を、どこにも負けない価格で、世界各地に送料無料で」＋「ベストセラーを閲覧する」。品揃え・価格・送料無料の約束とソーシャルプルーフ。
  - **Society6**：ツールチップ「カートは空です… 今のところ。でもここを見れば夢中になるはず」＋「ここからスタート」。カートページ「カートは空です。でも何か欲しいのでは？」＋「厳選コレクション」。

### 3. 検索結果のエンプティステート（p.133〜135）
- よくあるのは「このクエリの検索結果はありません」「入力されたバリューに該当する結果は見つかりません」。システムの説明や「クエリ」「バリュー」などの用語は避ける（専門用語は仕事の現場だけ）。**検索のやり直しだけを勧めるのも避ける**（同じことの繰り返しは嫌われる）。「結果なし」で済ませるのも問題。行き止まりに放り出さず、次の行動へ導き、探検を続けてもらう。
  1. **状況を説明する。**見つからなかったことをきちんと伝える。共感的な言葉、場合によってはユーモアも。
  2. **次のいずれかの対策：**
     - a. 同じ情報を探す別の方法を提案（カテゴリーで探す、より一般的／特定的な言葉、誤字脱字の確認、類義語）。
     - b. 条件に近い情報を提供（同じ作り手の他のもの、同様の仕様、同様の種類・機能）。
     - c. 「もしかして〇〇ではありませんか？」（よく似たキーワードがある場合）。
  - どれを選ぶにしても、ユーザーが検索で何を達成しようとしているかを理解し、その目的にできるだけ近づける提案を。
- 事例：**Zappos**（「やり直してみましょう：①誤字 ②スペース ③特定的な言葉はできるだけ使わない」＋新しい検索ボックス）、**Gmail**（詳細検索オプションへ）、**Google マップ**（「条件や対象エリアを変更してみてください」＋「エリアを追加しますか？」）、**Kickstarter**（「おっと！ 結果が見つかりませんでした。farm のことですか？」＋範囲を広げる＋人気のプロジェクト）、**eBay**（「お探しの情報が見つかりませんか？ 検索を保存すると、更新されたときにお知らせメールを受け取れます」）。

**Soto への示唆：**
- サイト：shop、plans、reservation、referral など、まだ商品や紹介実績がない画面がある。「準備中です」「まだありません」で終わらせず、ここで何ができるようになるか、今できること（先行登録、開発レターを読む）を示す。referral で紹介がまだ0人なら、「まだ0人です」ではなく、紹介すると何が起きるかを伝える。
- 製品（端末そのもの）：Soto は通知やフィードが少ない端末なので、空の画面が日常になる。「通知はありません」ではなく、静かな画面そのものを価値として語れる場所。例の方向性：「新しい知らせはありません。外の時間をどうぞ。」※端末UIは試作段階なので、方針としてメモ。
- 地図（Soto Map）や記録の機能を作るなら、最初の空の状態で「最初の一歩を記録すると、ここに残ります」のように、これから得られるものを書く。

## 16. 第10章 プレースホルダー（p.136〜151）

章の内容：プレースホルダーが適する状況と適さない状況／6種のプレースホルダーとその使い方。

### どんな状況に必要か、そしてより重要な問題として、どんな状況には適さないか（p.137〜140）
- プレースホルダー＝入力欄にあらかじめ置かれた薄いグレーの文字。入力を始めると消えるか移動する。
- スマホの小さな画面のために、ラベルをプレースホルダーとして入力欄に入れる方法が一般化し、デスクトップでも通例に。普及しすぎて、ラベルの横にラベルと同じ文字のプレースホルダーまで置くケースが増えた（「受取人の氏名」の欄に「受取人の氏名」）。少し工夫しても「メールアドレス」欄に「あなたのメールアドレスを入力してください」程度。
- **基本原則2つ：**
  1. **ラベルとプレースホルダーを区別する。**ラベルの唯一の役割は、入力すべき情報を伝えること。ラベルを入力欄の中に入れると、入力を始めた途端に消えて戻らず、短期記憶に負荷がかかる。ログインで2つ並んでいると、1つ目にメールを入れた後「最初の欄は何だった？」となり、消して確かめる羽目に。
     - 解決策の一つ：消すのではなく、入力欄の上や横に移動させる（eBay の例）。
     - より望ましいのは（スペースがひどく足りない場合を除き）、**ラベルを独立させ、入力欄の外側に置き、目立つ色でずっと表示しておく**（アクセシビリティの面でも。第18章）。見間違えや見落としの心配がなく、すぐ理解できるフォーム。スペースに制約があれば、ラベルは横ではなく上に。
  2. **もっともな理由がない限りプレースホルダーは使わない。**フォームは初めて見たときにできるだけシンプルに見えるように。文字がぎっしりだと根気が要り、作業も多そうに見える。自力で最後までやる画面では、**できるだけ文字を少なく**。
     - ラベルとプレースホルダーを両方置くと同じ文字が二重になり、ごちゃごちゃする。プレースホルダーを消してラベルを正しく出せば、すっきりする。
     - 空白の入力欄はすぐに視線を捉え、入力しようという気持ちを起こす。情報を提供してほしいなら、その受け皿を用意する。
     - 参考：ケイティー・シャーウィン（ニールセン・ノーマン・グループ）"Placeholders in form fields are harmful"。アイトラッキング研究では、視線が真っ先に引き付けられるのは空白の領域。何か書かれていると見分けるのに時間がかかり、最悪は入力欄を見落とす。
- 空きスペースを埋めるためにプレースホルダーを置かない。相応の理由があり、特定の目的に役立つ場合のみ。

### TIP18 あれ、文字数はいくつだっけ？（p.140）
- 入力のヒントや指示をプレースホルダーに入れない。入力を始めた後に確かめたくなっても、消えている。パスワードの規定、入力値の制約、文字数の上限などは、ラベルの下に表示するかツールチップで。入力を始めてからでも確認できることが大切。

### プレースホルダーはどのような場合に役立つか（p.141）
1. **ぜひ入力してほしい欄。**ホームページの一番上の検索ボックス（行動を促すメッセージ＋検索ボタン）。プロダクトの主要な目的に欠かせない欄（Facebook のステータス、出会い系のプロフィール）。
2. **答えにくい質問や、敬遠されそうな質問の回答欄。**何通りも答え方がある質問、考えをまとめる必要があるオープンクエスチョン、答えを特定しにくい質問、慎重に扱う情報、抵抗感を抱かれやすい質問。プレースホルダーが障壁を取り除き、不安なく答えられるようにする。
3. 単純にユーザーを笑顔にしたいとき（章の最後で解説）。

### 6種のプレースホルダー（p.142〜）
- **タイプ1：質問。**重要な入力欄に興味深い個人的な質問があると、答えたくなる。二人称（あなた）で直接問いかけ、面白がって乗り気になり、短く答えられる質問に。**Airbnb**：「ようこそ我が家へ。190余りの国々で、地元のホストがあなたのために宿泊先を提供します」＋検索欄「どこに行きたいですか？」。答えを持っていない人はいない。答えるだけでなく、憧れの地を調べたくなる。**Booking.com**：「どこに行きましょうか？」。

- **Fiverr**：見出し「夢見るだけでなく、実現しよう」から続けて検索欄「どんなサービスをお探しですか？」。上の言葉から続けて読むと、希望を書き込めば何でも実現するという約束になる。どんな言葉を入れればよいかも伝える。
- **Udemy**：「何を学びたいですか？」。ホームページの問いかけは、ユーザーが自分なりの答えを見つけ、利用を始めるよう促す。最大の関心事に一気にたどり着ける質問で、階層メニューの回りくどさがない。
- サポートページでも：**WeTransfer**「何をお手伝いしましょう？」。
- 回答のスタイルは、どんな質問をするかで決まる。**Twitter**「いまどうしてる？」（外で起きていること）、**Facebook**「キネレットさん、その気持ち、シェアしよう」（頭の中のこと）。

- **タイプ2：カテゴリー。**カテゴリーを示すと選択肢が絞られ、もっとも望ましい使い方を簡単に見つけられる。**SoundCloud**「アーティスト、バンド、楽曲、ポッドキャストを検索」、**Hipmunk**「都市名、空港名、ホテル名」、**SimplyHired**「ジョブタイトル、スキル、または会社名」「都市名、州名、または郵便番号」、**Pixabay**（カテゴリー＋欄の下に人気の検索ワード「愛、壁紙、朝、音楽、花」）。
- **タイプ3：具体例**（複数でもよいが**最大3つまで**）。**Tailor Brands**「あなたのビジネスのことを、もう少し教えてください。そうすれば、あなたにぴったりのロゴをデザインできます」＋「例：私たちはウィリアムズバーグにある小さなオーガニックショップで、ターゲット層はおしゃれな若者たちです」（規模、業種、拠点、ターゲットが一目で分かる）。**PayPal** 受取人へのメモ「"お取引をありがとうございます"など」。**Udemy** 講師向け（受講対象者・必要な知識の例文）。**Canva**「何をデザインしたいですか？」＋「"ソーシャルメディア"と入力」など、訪問のたびに例が入れ替わる。
- **タイプ4：助言。**オープンクエスチョンでは、作業の最中に考え込まされるのを何より嫌う。望むのは欄を埋めて前に進むことだけ。回答欄のプレースホルダーで正しい方向に導き、重要ポイントを伝える。**RealMatch**「カバーレターを添付しましょう！ 大勢の中で存在感を示せます。通過率が最大25%アップ！ あなたのスキル、経験、持ち技を余すところなく」。**Airbnb** 体験ホスト「ゲストが独力で探し当てられない、たどり着けない特別な場所があれば、ぜひ紹介してください」。
- **タイプ5：障壁の解消。**答えるのを踏みとどまらせる障壁を取り除く。**OkCupid**「私はしょっちゅう、こんなことを考えています」→「地球温暖化、ランチ、次の休暇…何でもオーケーです。さあ書きましょう」。重要な関心事・ささやかな関心事・ごく一般的な関心事を並べ、「取るに足らないかも」「深刻すぎるかも」という不安を消す。
- **タイプ6：楽しい雰囲気作り。**楽しませるためだけに使うことも。ただしフォームはできるだけ短時間で完了できることが最優先なので、**入力フォームには総じてジョークは似合わない**。例外は、ブランドのボイス＆トーンに遊び心が不可欠で、プロダクトにも似合い、ユーザーが時間に追われず楽しめそうな場合だけ。**Trello**（メール欄に架空キャラクターのアドレスが入れ替わり：dana.scully@fbi.gov など）、**Typeform**（Bruce Wayne、bruce@wayne.com、パスワード欄「秘密にしておきます」）。

**Soto への示唆（今のフォームを見て）：**
- 先行登録の下のフォーム：ラベル「メールアドレス」を外に出し、プレースホルダーは「you@example.com」（形の例）。ラベルとプレースホルダーが別の役割で、本の原則どおり。お問い合わせも同じ形で、本文欄にはプレースホルダーがない。良い状態。
- トップのフォーム：ラベルは画面上は隠し（読み上げ用だけ）、プレースホルダー「メールアドレス」がラベル代わり。欄が1つだけで、何を入れるか迷わないので、本の基準でも許容範囲。ただし一部のパターンでは「メールアドレス（送り先）」になっている。入力を始めると消えるので、補足を入れるならラベルかボタン下の小さな文に。
- 「you@example.com」はエラーの文（例：you@example.com）とも一致していて一貫している。
- 将来、端末の初期設定や Soto Map で入力欄を作るなら、タイプ1（質問）が使える。例の方向性：「今日はどこへ出かけますか？」「最近、外で何をしましたか？」のように、外の時間に目を向ける問いかけ。答えやすく短い質問に。
- コラムに検索はない。将来つけるなら、結果ゼロのとき「やり直してください」だけにせず、近いテーマのコラムを並べる。
- お問い合わせの本文欄（今は空欄）は、タイプ4・5が効く場所。例の方向性：「例：子どもに持たせたい／LINE は使えるか知りたい／お店で扱いたい」のように、具体例を3つまで。ただし空白の欄のほうが視線を集めるという研究もあるので、入れるなら短く。
- 入力フォームでのジョーク（タイプ6）は Soto では使わない。

## 17. 第11章 ボタン（p.152〜161）

章の内容：コンバージョンボタンのライティングの基本原則／クリックトリガーとは何か、どう使うか。

### 適切な言葉が結果を生む（p.153）
- ボタンは決心が行動に移されるかの分岐点。どれだけ重視しても過大評価にはならない。時間をかけて丁寧に言葉を選び、できればテストにも時間を。ありふれた言葉で妥協すると、ゴールの直前で減速する。
- **テスト、テスト、テスト。**ボタンの一語を変えるだけでコンバージョン率が劇的に増減することもある。A/Bテストを。基本原則を知るのは、2つの冴えない選択肢ではなく、2つの優れた選択肢を比べるため。

### 「どうやって手に入れるか」ではなく「何を手に入れるか」（p.153〜155）
- 「ダウンロード」「検索」「送信」「登録」などの一般的な言葉は、決意を固める助けにならない。プラスとマイナスを自分で秤にかけ、それまでの情報を思い出し、クリックする価値があるかを自分で判断しなければならない。しかも、片付けなければならない面倒な作業を連想させる。
- マイケル・アーガード（4年間ボタンをテスト）の方程式：**価値＋レレバンス（関連性、自分との結び付き）＝コンバージョン**。
  - 価値："How to Write a Call-to-Action that Converts"。ボタンには、ユーザーが**やること（行動）**ではなく、**得るもの（価値）**を。「オーダー・インフォメーション」→「ゲット・インフォメーション」でコンバージョン率が40%近く上がった。行動だけを伝えると判断をユーザーに委ねることになるが、価値を書けば探し求めている最終結果そのものを提示できる。
  - レレバンス：「無料でダウンロード」ではなく「無料ガイドをダウンロード」、より望ましいのは「無料ガイドをゲット」。特定の状況に関連付けた言葉は、コンバージョン率を何十パーセントも高める。レレバンスがあれば、言葉が長くても上がる。ただし鵜呑みにせず、自分のサイトで確かめる。
- **注意：すべてのボタンが重要な価値を提供するわけではない。**ここで話題にしているのは、会員登録、リードジェネレーション、ダウンロードなど、コンバージョンや重要な行動に直結するボタン。プロダクトにとって重要な行動が検索やコメントなら、それらのボタンに力を入れる。
- ボタンの大半は機能を伝えるもので、そのままでよい。むしろそのままにしておくべき。続行、買い物かごに入れる、チャットに参加する、安全な支払い、編集、共有、保存などは標準化されていて分かりやすく、使い慣れている。

### 事例：電子インボイスの3パターン（30日間の無料トライアル）（p.155〜156）
| | ホームページのボタン | フォーム最終行のボタン |
|---|---|---|
| 1 | 今すぐ会員登録 | アカウント作成 |
| 2 | 今すぐ会員登録（30日間無料トライアル） | 無料トライアルを開始 |
| 3 | 今すぐ会員登録（30日間無料トライアル、コミットメントなし） | システムの利用を開始 |
- パターン1：やらなければならない行動だけ。得られる価値が分からず、レレバンスもない。どんなプロダクトにも使い回せる。
- パターン2・3のホームページのボタン：行動に続けて価値を添えている。ただし、ホームページのボタンなら**価値だけ**を書くほうがさらに良いかも（30日間の無料トライアルのことだけ）。「登録」が面倒な作業を連想させると手が止まる。
- フォーム最終行は、最終的な価値＝インボイスの作成を。「システムの利用を開始」はレレバンス不足で汎用的、面倒な作業の印象もある。レレバンスを高めるなら「**電子インボイスの作成を開始**」。
- **Unbounce**：「このランディングページビルダーのプレビュー」「アンバウンスがどんな風に役立つかを見る」「30日間の無料トライアルを開始」。価値が詰まったやや長めの言葉でも、ユーザーには重要な情報。ボタンのマイクロコピーは必ずしも短くなくてよい。

### 多彩な参考事例（p.157）
- 登録→「ポートフォリオを作る！」(Carbonmade)、「はい、新作のパターンとテストを送ってください」(GoodUI)、「割引コードのロックを解除」(The Middle Finger Project)。
- 検索→「仕事を探す」(Indeed)、「条件にぴったりの航空便を探す！」(Loco)。
- 開始→「履歴書を作成する」(MyPerfectResume)、「無料で求人情報を掲載」(ZipRecruiter)。
- 決済→「席を予約する」(Leadpages)、「今すぐ気持ちを10倍安定させる」(The Middle Finger Project)。

### コラム：一連の購入手続きに使うボタンは、普通が一番（p.156〜157）
- 「カートに追加」は商品をカートに入れるだけで、それ以上の意味はない。まだ責任もなく支払いも始まっていない。だから**定型文以外の言葉は、ユーザーを不安にさせるだけ**（「これが欲しい」「これを選ぶ」は、どこに連れて行かれるのか分からないと思わせる）。
- 支払いを確定するボタンも分かりやすく。言い換えてもせいぜい「あんしん決済」「セキュア決済」（第16章）。本当に手続きを進めたい人以外が押さないように、最後のボタンは「支払いを確定する」「購入する」など、ごく普通の言葉で。
- ユニークUIの調査（ヘブライ語）：購入手続きが標準的な方法と違うとコンバージョン率が低下する。規格外の試みはしない。

### TIP19 会員登録をする気になった理由を思い出させる（p.158）
- 登録ボタンには「登録」ではなく、登録を終えたユーザーが受け取るベネフィットやできるようになることを：「レシピを保存する」「フランス語を学ぶ」「プロ仕様のロゴを作る」「あなたにぴったりの仕事を見つける」。
- 割引やギフトがあればボタンに：「年会費無料のクレジットカードを入手」「25%オフで買い物！」。手続きではなく、登録する気になった理由に意識が向く。

### TIP20 これは一体何をキャンセルするボタンなのか？（p.158）
- 「操作をキャンセルしますか？ ［キャンセル］［取り消し］」では、キャンセルが直前の操作を取り消すのか、キャンセルのリクエストなのか分からない。
- 「はい／いいえ」に置き換え、少し言葉を足して意味を明確に。**Eventbrite**：「無料の注文をキャンセル。本当にこの注文をキャンセルしますか？ ［はい、この注文をキャンセルします］［いいえ、その必要はありません］」。

**Soto への示唆（サイトのボタンを全部見て）：**
- すでに価値型のボタンがある：「料金が決まったら知らせてもらう」「始まったら知らせてもらう」「登録して、紹介リンクをもらう」。何が手に入るかが書いてあり、本の原則どおり。
- 一番大事な「先行登録（無料）」は、本の分類では行動型（登録）。「無料」で金銭の障壁は消しているが、価値とレレバンスはない。
  - 価値型の方向性（決定ではなく、A/Bテストの候補）：「発売の案内を受け取る（無料）」「最初に知らせてもらう」「番号を受け取る」（先行登録券がある場合）。
  - 今のA/B案にある「最初に見る」は価値型に近い。「先行体験に登録」は行動型。
  - ただし TIP の注意どおり、ナビの「先行登録」は変えない（ユーザーが探す言葉）。変えるのはフォームのボタンだけ。サイト全体の用語統一（先行登録）とも両立させる：ボタンは価値、その下の小さな文で「先行登録は無料です」。
- 英語版「Join the waitlist」は行動型（Join）。価値型なら "Get launch news first" など。日本語版と同じ方針で揃える。
- 「送信する」（お問い合わせ）は機能ボタンなのでこのままでよい。
- 将来の購入画面（shop）では、カートと支払いのボタンは「カートに入れる」「購入する」「支払いを確定する」など普通の言葉に（遊ばない）。
- 解約・配信停止の確認画面を作るときは TIP20：「はい、配信を止めます」「いいえ、このまま受け取ります」のように、何をするボタンか分かる言葉で。断る側の言葉で相手を責めない（コンファームシェイミング禁止）。

### クリックトリガー、次の局面に進むための最終メッセージ（p.159〜161）
- ジョアンナ・ウィーブ "Buttons and Click-Boosting Calls to Action"：ボタンのすぐ近くの短いメッセージ（**クリックトリガー**）も、ボタンの言葉と同じくらいコンバージョン率を劇的に上げる。
- 目的：次に進むか決める瞬間に、的確な言葉で後押しする。ボタンの隣（上か下）に**少なくとも一つ**書き添える。配信登録、ユーザー登録、動画視聴、購入、何でも有効。
- 働き：①クリックで得られる価値を改めて認識させる ②**クリックに付随する障壁を取り除く**。
- 書くときは、ユーザーの目的と、それを阻むもっとも大きな障壁を検証して言葉を選ぶ。別の場所で対応済みでも、ボタンの隣で再確認できると非常に効果的（第16章）。
- 2〜3種類を併記してもよいが、しつこくならないように。言葉を厳選し、A/Bテストを。
- 事例：
  - **Intercom**：メール欄＋「始める」の下に「14日間の無料トライアル・セットアップは簡単・いつでもキャンセルできます」。3つが一体となって、簡単に使えて良いこと尽くし、気に入らなければ費用も時間もかけずにやめられると伝える。
  - **Booking.com**：「直近の予約：5分前」「本日の予約数3件」「現在1人が閲覧中」「残り1部屋！」。ソーシャルプルーフと、早い者勝ちの印象。
  - **Airbnb**：「予約」の下に「まだ料金は発生していません」（マイナスを減らす）＋「多くの人がこの部屋に興味を持っています。先週の閲覧回数301回」（プラスを膨らませる）。
  - **Showpo**：「サイズ14（新品）は残り1点、急ぎましょう！」。
  - **Society6**：「決済をする」の下に「保証は十分：無料で簡単に返品できます」。返品の不安を解消。
  - **Download.com**：評価の星とユーザー投票数をボタンの上に。
  - **InVision**：ボタン本体に「始める、ずっと無料」。

**Soto への示唆：**
- 今のサイトにはすでにクリックトリガーがある：ボタンの下の「試作機ができたら、登録してくださった順にご案内します。」（価値）、「無料です」（障壁）。良い状態。
- 一番大きな障壁（迷惑メール、後から請求、手間）への答えを、ボタンの直下に一行で：例「無料・お支払いなし・メールは月1回・いつでも解除できます」（Intercom 型の3〜4点並び）。今は「登録について」の折りたたみの中にある内容なので、新しい約束ではない。
- Booking.com / Showpo 型の「残りわずか」「急ぎましょう」は Soto では使わない。焦らせる手法は「お誘い」の原則とブランドの静けさに反し、事実でなければ不誠実。使うなら「No.300 まで番号を刻めます」のように、実際の条件だけを淡々と書く。
- 登録者数のソーシャルプルーフ（Airbnb 型）は、実数がある程度になってから、盛らずに。

## 18. 第12章 404エラー：ページが見つかりません（p.162〜169）

章の内容：あらゆる404ページのライティングの4原則／404ページのブランド化を成功させるアイデア。

### インターネットのブラックホール（p.163）
- レニー・グリーソン（TED「404, the story of a page not found」）：「あなたの何が他と違うのか、なぜ私はあなたを好きにならずにいられないのか。単純なミスは、そういうことを改めて思い出させます。」
- 404は、消えたページ、元々ないページ、アドレスが変わったページへのリンク、URLの打ち間違いで出る。
- 「404エラー：ページが見つかりません」だけだと、ユーザーは即座に「戻る」を押し、失われる。別のページを見てくれる可能性はほぼゼロ。404ページは、ミスへの対応、ユーザーが困ったときに何ができるかなど、ブランドが浮き彫りになる場。
- ありきたりなメッセージしか書けないなら、ユーザーか問題を理解していない。現実的にも感情面でも行き止まり。ビジュアルで笑顔にできても、マイクロコピーがなければ目的地に導けない。

### 404ページのマイクロコピーの書き方（p.164）
1. **何が起きたのか、なぜここに辿り着いたのかを伝える。**「404」や「エラー」を持ち出す必要はない。専門用語なしで、ページが見つからない／存在しないと簡単な言葉で。数字を使ってもよいが主軸にしない。
2. **共感を示す。**探していたものが見つからず、私たちのせいかもしれない。いずれにしても落胆しているので、お詫びや気持ちを汲む言葉を。
3. **脱出方法を提供する**（少なくとも一つ）：サイトの中心部や人気のカテゴリーへのリンク、検索ボックス、ホームページへのリンク、メインメニュー（言葉やビジュアルで注意を向ける。自力で見つけるのを期待しない）。
4. **あってもなくてもよい要素**：凝ったデザイン、ネガティブをポジティブに変えるユーモア（混乱しているユーザーを笑うのは厳禁）、リンク切れを報告する方法（「他のサイトから来た方は、どこから来たか教えていただけると助かります。リンクを直して、他の方がここに来なくて済むようにします」）、お問い合わせへのリンク、問い合わせ先の一覧。

### 事例（p.165〜166）
- **Belle and Sue**：文字だけ。「大惨事！ 悲劇！ 不祥事！ クビになるかも！ お探しのページに問題が生じています。別のページに移動するか、しばらくここで休憩し、平和で静かなひとときをお楽しみください。」イライラを受け止めつつ別の視点。
- **Spotify**：回転するレコードの絵＋「404とハートブレイク。お探しのページは見つかりませんでした。FAQ またはコミュニティがお役に立つかも」＋「戻る」。ただ「戻る」の行き先はホームなので「ホームへ」と書くべき（ホーム以外から来る人もいる）。
- **RSPCA**（英国動物虐待防止協会）：「お探しのページは、どうやらイヌが持って逃げたようです。裏庭に埋めたかも。ちょっと見てきますので、その間に下のリンクが役立つか見てください」＋引き取り・アドバイス・活動への協力。キュートで実用的、協会の理念も伝わる。
- アイデア（マイクロコピー以外）：楽しいイラストや画像、イライラを表すグラフィック、アニメーション、理由を説明するブランドのボイス、歌や映画からの引用、動画。

### ブランドの事業内容を伝える404ページ（p.167〜168）
- 404は、なぜそのブランドを愛しているか、なぜここに来たかを思い出してもらうチャンス。エラー対応だけでなく、関係づくりの役割も果たせる。ページが見つからない理由を、事業内容に関連付けて考え、特徴的な言葉を織り込む。
- **IMDb**：映画のセリフをもじる（「ウェブページ？ これから行くところに、そんなものはいらないよ」バック・トゥ・ザ・フューチャー）。約15通り。
- **TripAdvisor**：「このページは休暇で旅行中です… あなたもぜひそうしてください。私たちが200以上のサイトを検索し、もっともお得なホテルを見つけます」。
- **Financial Times**：「なぜこのページが見つからなかったのでしょうか？ 一流の経済学者たちに尋ねてみました」→スタグフレーション、マネタリズム、効率的市場仮説、モラルハザード、コモンズの悲劇など22通り。
- **NPR**：「お探しのページはどこかへ消えてしまいました。でも少なくとも良い仲間がいます」→アメリア・イアハートなど、失われて戻らない人々・物事の記事。
- **Unique UI**：「私たちにこんなことが起きたのは初めてです、本当です！ 今朝はコーヒーも飲めず、リンクが混乱しました。本当にすみません。解決するまで、こんなページはいかが？」責任を持って対処することを伝え、リンクを提供。

### コラム：広く全体を視野に（p.169）
- Google（Android の404のゲーム）、ロメイン・ブレイジャー（レミングのゲーム）など、404に力を入れるサイトも多く、「最強の404ページ30選」のような記事も無数にある。
- けれども正直、遊び心を一番面白がっているのは作り手自身。ユーザーがこのページを見る機会は限られ、長く留まりたくない。本来探していた情報に向かって進みたい。
- 興味を引くのも大切だが、それより**必要な情報を不足なく提供すること**。デザインはシンプルか、ちょっと楽しいビジュアルを。微量のユーモアのある分かりやすいメッセージと、**サイトの中心部へのリンクを3つくらい**で申し分なし。
- 余談：好評な404はシェアされ、マーケティングになる（Nosh の動画など）。

**Soto への示唆（サイトを確認して）：**
- サイトに 404.html がない。Cloudflare Pages は 404.html がないと、存在しないURLにもトップページを返す（SPA 扱い）ので、「見つからない」と伝わらず、検索エンジンにも同じ内容のページが大量にあるように見えうる。※Cloudflare の挙動は実装前に公式ドキュメントで確認する。
- 作るなら、本の4原則で：①簡単な言葉で「このページは見つかりませんでした」 ②一言のお詫び ③リンク3つ（トップ、コラム、先行登録）＋お問い合わせ ④ユーモアは微量か、なしで。
- ブランドに関連付けるなら（TripAdvisor 型）、方向性の例：「このページは、外に出かけてしまったようです。」のように「外」と結びつける。押し付けず、静かに。決定前に関係性・人格と照らす。
- 長く留まらせる仕掛け（ゲーム等）は作らない。目的地に早く戻すのが Soto の価値観（画面の時間を減らす）にも合う。

## 19. 第13章 待ち時間（p.170〜177）

章の内容：待ち時間のエクスペリエンスを丁寧に設計することがなぜ重要か／ユーザーと一緒に待ち時間を過ごすためのアイデア。

### ユーザーと過ごす有意義な時間（p.171）
- 待ち時間＝ページの読み込み、データ処理、検索、ダウンロードなどの完了を待つ時間。
- タル・ミシュアリの研究：動画、時間とともに変化するテキスト、バーなど、注意を向けられるものがあると、**知覚上**の待ち時間は短くなる。
- ただ画面を眺めて待つ時間は、自由に使ってよい時間。知的な話題、心温まる話題、ブランドの特色が感じられる話題を差し出せば、最小限の投資で思いがけない楽しみを。大切な存在だと認識していることが伝わる。小さな工夫の積み重ねが、すべてを大きく変える。
- 言葉を一切使わずグラフィックだけでもよい。予算があれば楽しいアニメーションは素晴らしい。ただ言葉を並べるほうがはるかに簡単で、時間も費用もかからない。

### 特定の雰囲気でユーザーを包み込む（p.172〜）
- **InVision**：「あなたのためのエクスペリエンスを読み込んでいます」。
- **Wix**：「読み込み中…良い感じの流れが来ています」。
- **8tracks**：「あなたが来るとは思わなかったので、だいぶ散らかしています…」。ちょっとお茶目。

- **8tracks** の後にも続く事例。

### システムがどんな処理を実行中かを伝える（p.175〜176）
- 何かのプロセスが進んでいると、ユーザーはその経過を追い、時間を忘れ、自分も参加している感覚になり、完了後の成果への期待も抱く。
- **Shopify**：「動かずに待っていて！ あなたの店を作っています。3ページ中1ページ目、アカウント作成中」。
- **Tailor Brands**：「完璧なロゴをデザインしています 18%／名刺を作成しています 48%／ソーシャルポストのプランを立てています 100%」。自動でも十分な検証を経て完成すると実感させる。
- **OkCupid**：登録の最後に「素敵な人たちを見つけています！」。訪問した目的そのもの。
- **Videostream**：「読み込み中、ジャガイモをすりつぶしています…／リスを追いかけています…」などユーモラスなストーリー。

### プロダクトの上手な使い方のヒントを提供する（複雑なシステムで特に有効）（p.176）
- **Google 広告**：アップロード中に毎回変わる簡単なヒント（「テーブルを拡大するときは、ここをクリック」）。時間つぶしだけでなく、特長を伝える。

### 待ち時間が長くなりそうなときは、その間別の作業をやることを勧める（p.177）
- **Twitter Counter**：「1〜2分お待ちください！ データ収集を開始しました。すぐに詳細な分析とアドバイスをお届けします。その間、コーヒーをいかがですか？ または［ウィキペディアのおまかせ表示をチェックする］」。
- **HouseParty**：友達の参加を待つ間に「医者が言うには、友情は人を長生きさせるらしい」「笑顔は19種類ある」「オンブロファイルとは、雨が大好きな人たちのこと」。友達が来たときの会話のネタにもなる。

**Soto への示唆：**
- サイトの待ち時間は、登録ボタンを押した後の「送信しています…」程度。数秒なら今のままで十分（短く実用的に）。
- 製品では、端末の起動、アップデート、初期設定の待ち時間が該当。ここは「画面を見て待つ時間」なので、Soto らしく「画面を見なくていい」ことを伝える場所にできる。方向性の例：「数分かかります。そのあいだ、窓の外でもどうぞ。」※端末UIは試作段階なので方針メモ。
- 長い待ち時間（初期設定、アップデート）は Twitter Counter 型が Soto の価値観にいちばん合う：「別の画面を見て待つ」ではなく「画面から離れて待つ」ことを勧め、終わったら音か振動で知らせる。
- 何をしているかを段階で示す（Shopify 型「3ステップ中1つ目：LINE を準備しています」など）。進み具合が分かれば、画面を見続けなくてよい。
- HouseParty 型の「豆知識」は、外の時間の小さな話（季節、歩くこと、退屈の効用など）なら Soto らしい。ただしコラムの研究に基づく事実だけにする。

## 20. Part 3 ユーザビリティ（p.178〜）

### 障害を取り除き、流れを整える（p.179）
- 人がプロセスを放り出すのに大した理由は要らない。入力方法が一箇所だけ分かりにくい、手間取りそう、プライバシーの不安が少し消えない、答えづらい質問がある――ひとつで十分。途中で一度つまずくか、問題の兆しが見えるだけでギブアップする人もいる。
- 良質のマイクロコピーは、障害が起きかねない場面に必ず現れ、即座に解決策を出す。ときには障害の発生そのものを防ぐ。
- Part 2 までは主に行動の「前後」のマイクロコピー。Part 3 は行動と「同時に」働き、助言して、タスクを簡単に手早く完了させるもの。
- 章構成：14 基本原則／15 疑問に答え、知識のギャップを埋める／16 不安や懸念を軽減する／17 エラーやトラブルを防止する／18 アクセシビリティ／19 高度なシステム。

## 21. 第14章 マイクロコピーとユーザビリティ：基本原則（p.180〜193）

章の内容：できるだけ簡潔に／フォーム画面にマイクロコピーを表示する4通りの方法／マイクロコピーが必要な場所の見つけ方。

### できるだけ簡潔に、ただし…（p.181）
- ユーザーが実際に行動を始めたら（登録、注文、新しいプロジェクト）、マイクロコピーの目的は変わる。**ユーザビリティを高め、障害を取り除き、手早く簡単に完了できるようにする**こと。感情に訴える段階は終わり。重視するのは分かりやすさと実効性。基準は楽しませることではなく、最小限の努力（スティーブ・クルーグの言う最小限の思考）でタスクを完了できるよう支えること（楽しんでもらおうという姿勢は持ち続ける）。
- ただし、法律用語のような無表情な定型文に戻るという意味ではない。必要な局面でだけ、できるだけ少ない言葉で助言する。自力で送信ボタンまで辿り着いてほしいなら、不要なユーモアや余計な指示は持ち込まない。
- **必要なときだけ、正確に、簡潔に、シンプルな言葉で。**

### 説明だらけのフォーム（p.182）
- 名前・メール・パスワードだけのフォームに、説明文がびっしり（「この名前が友達の画面に表示されます」「名前は4〜40文字」「このアドレスをログインに使います」「第三者に提供しません」…）。良かれと思っても、文字だらけで読む気を失わせる。
- 「文字数は5文字から40文字までです」ではなく「5〜40文字」。
- 書く前に自問：①この言葉は本当に必要か？ ②どうすれば最少の言葉で言い表せるか？

### UXデザインをチェックする（p.183）
- 言葉で念入りに説明したくなる、的確な言い方が見つからない――それは UX デザインの問題かもしれない。マイクロコピーの役割は、デザインで対応しきれない問題を解消する以上のものではない。説明だらけになるなら、デザインを見直す。

### その一方で、必要なら躊躇せず援助の手を差し伸べる（p.183）
- 問題は分量ではなく、**ユーザーが実際に援助を必要としているか**。
- サラ・ウォルシュ（Capital One）：フォームの言葉を2倍に増やし、入力欄の周りに操作上のアドバイスを書き加えたら、完了率が26%→96%（約3倍）。"Don't forget your online forms"。
- 迷ったり、ミスしたり、安全性に不安を感じそうな箇所には、解決の言葉や確証を与える言葉を、ためらわず書く。口出ししすぎないつもりで重要な説明まで省くのは禁物。困ったときに助言してもらえるのを喜び、問い合わせも諦めもせずに済む。
- 指示は短く。本当に必要になるまで非表示にしておく方法もある。

### フォーム画面にマイクロコピーを表示する4通りの方法（p.184〜188）
1. **静的表示**：入力欄の前かすぐ隣に、ずっと表示。利点：見落とされない。欠点：フォームがやや見づらくなる。最適：理解に指示が不可欠で、見落とされては困るとき。**Munchery**：「一旦送信したメッセージは変更できないので、事前にダブルチェックしてください」。この種の指示は（アクセシビリティ上）**入力欄より前に**置く（第18章）。
2. **オンデマンド表示**：アイコン（?、!、i）をクリック／マウスオーバー、またはリンクで表示（ツールチップ）。利点：いつでも参照でき、慣れた人は読まずに済む。欠点：クリックしない人は重要な情報を受け取り損ねる。だから重要な説明はツールチップに入れず、欄のそばに表示（著者）。最適：a. 情報や指示が多く画面がごちゃごちゃするとき b. 基礎知識や背景説明（行動の方向付け、価値を伝える） c. 繰り返し行う行動。**Booking.com**「出張です」の？：「朝食、WiFi、無料駐車場など、出張に適したサービス情報を提供します」（個人情報を聞く理由）。**Facebook 広告**：各欄の隣に i アイコン。
3. **自動表示**：必要なタイミング（入力欄にフォーカス）で自動表示し、別の欄に移ると消える。利点：必要なときに読め、それ以外は文字を減らせる。欠点：もう要らない再訪ユーザーにも毎回出る。最適：a. 情報や指示が多い b. 1回限りの行動（ショップ開設、アカウント作成、クラウドファンディング開始、ツアー予約） c. **サポート担当者がすぐ近くにいる印象を与えたい**（金銭、入学手続き、高額商品の購入） d. 重要だが不定期の行動（航空券の購入）。**Wizzair** パスワード（「最少7文字、最長16文字…」→もっと短く「7〜16文字／数字と英字を必ず使用／特殊文字は不可」）。**Wix**（代替テキスト欄で「画像が見えない人のために、何が写っているか一言二言」）。**Zeplin**（メール欄で「確認メールをこのアドレスに送ります」、ユーザー名欄で「チーム全員の画面に表示されます。英字、数字、_ だけ。見本：aryastark」）。
4. **プレースホルダー**：入力欄の中の薄いグレー、フォーカスで消える。利点：見落とされない。欠点：消えると見られない。最適：a. 短い指示 b. 消えた後にもう一度見たくなる心配がないとき c. 書き出しの一文を提供したいとき d. 正しく記入できるよう短い文例を示したいとき（第10章）。
- 同じフォームの中でこの4通りを混在させない。一貫性はとても大切。ニーズに合わせて使い分け、ストレスなしで使えるフォームに。

**Soto への示唆：**
- 先行登録フォームはメール1つ＋地域（任意）＋先行体験チェック。説明の量は少なく、本の「簡潔に」に合っている。
- 一方で「援助が必要な箇所」は確認したい：①「試作機の先行体験にも参加したい」のチェックは、何をするのか（費用、期間、場所）が分からないと押しにくい。静的表示で一行（例：「1週間ほど使って感想を聞かせてください。参加するかは案内のあとで選べます」※実際の運用どおりに）。トップの別パターンには「参加するかどうかは、そのとき選べます」がすでにあるので、それを流用できる。②地域の欄は「なぜ聞くのか」が書いていない。Booking.com のように理由を一言（例：「近くで体験会を開くときの参考にします」※本当の用途だけ）。
- 「登録について」の折りたたみ（オンデマンド表示）に、無料・支払いなし・配信頻度という**重要な説明**が入っている。本の著者は「重要な説明はツールチップに入れず、欄のそばに」と言っている。これまでの章の結論（ボタン直下に一行）とも一致。
- お問い合わせの「送信したら変更できない」系の注意は不要（メールで追記できる）。書かないほうが簡潔。
- 端末の初期設定（LINE、eSIM など）は「1回限りの行動」かつ「サポート担当がそばにいる印象を与えたい」場面＝自動表示型の助言が最適。エラーより先に、つまずきそうな所で一言添える設計にする。

### TIP21 (?) か (!) か (i) かリンクか？（p.190）
- 「これはどういう意味？」「何をする機能？」「なぜこの情報が要る？」というよくある疑問なら **?**（疑問をそのまま記号化し、答えがここにあると示す）。
- 「この合計はどう算出された？」「どこを探せばデータが見つかる？」のような特殊な疑問なら、入力欄の隣に**テキストリンク**（「どう計算したか」「どこを調べればよいか」）。短くシンプルに。
- **! や i** は、答えというより背景説明や重要な補足情報のとき。
- 明確な基準ではない。迷うならどれでも大差ない。大事なのはマイクロコピー自体が効果的でシンプルで、疑問や懸念を確実に解消すること。

### マイクロコピーが必要な箇所の見つけ方（p.191〜192）
- 時間的な遅れ、誤解、不安、エラーが生じそうな箇所。ルーク・ウルブレフスキー『Web Form Design』から3つ：
  1. **ユーザビリティテスト**：記録を見て（ユーザーが発した言葉に注目）、遅れ・迷い・行き詰まりの箇所と、何を理解できなかったかを書き留める。短い説明文だけで解決することも。例：オートコンプリートの欄を、候補から選ばず全部自分で打つ人が多い→欄の下に「都市名を入力し始めるとリストが出ます。その中から選んでください」。
  2. **顧客サポート担当者**：最も多い問い合わせと、その理由を聞く。どこでつまずき、何が難しすぎるかが分かる。例：支払いを中断して電話で購入する人が多い→オンライン決済の安全性を繰り返し強調し、どんな対策をしているか伝える（第16章）。
  3. **モニタリングと解析ツール**：ヒートマップなどで、どこで放棄したか、最後に何をしたか、どこでエラーが多いかを見る。例：生年月日をスキップする人が多い→必須と示し、必要な理由（法律で必要など）を一言。

## 22. 第15章 疑問に答え、知識のギャップを埋める（p.194〜206、途中まで）

章の内容：マイクロコピーで答えを明示するべき4つの代表的な疑問。

### 知識の呪いを解く（p.195）
- ほぼすべてのデジタルプロセスは、ユーザーには理解しきれず不安を生む。設計者は全体が見えるが、ユーザーには目の前の1〜2ステップしか見えない。知らない用語に説明がない、使い方が分からない――それが不安を増し、プロセスと私たちへの信頼を失わせる。
- マイクロコピーは疑問にその場で答え、信頼感を与える。私たちがいつも寄り添っていて、疑問を抱くのはもっともだと理解していると示せる。
- **知識の呪い**：知識を持つ人は、知識のない人の視点から見られない。書き手にとって当たり前のことが、ユーザーには初めてのこと。「これは何？」「どんな機能？」「どう使えばよい？」にぶつかる箇所を見つけるには、**初めて取り組むつもりで全体を見直す**。テストとは別に、自分が新規ユーザーになったつもりで見直す。

### 疑問1：これは何？（p.196〜199）
- a. 全体を見直し、制作チーム内でしか使わない専門用語、ユーザーに馴染みのない用語を探し出す。b. よりシンプルな言葉に言い換えられないか。c. 言い換えられなければ、マイクロコピーで説明。
- **コモンウェルス銀行**：「カードPIN（個人識別番号）とは、商品の購入やATMでカードを使うときに入力する暗証番号です」。これは何？への答えなので ? アイコンのほうがよいかも。
- 機能に名前を付けるのは、プロダクト専用の新しいルールを作ること。ユーザーには簡単に理解できず、どんな価値があるかも分からない。**名前が何を意味し、何に役立つかを説明する**。**Monday.com**：「共有できるボード：チーム外のゲスト（たとえばクライアント）と共有」。
- **eBay**：配達予定日の出し方を説明。**The Noun Project**：PNG と SVG の違いと用途を説明（ただし ? はその先に情報があると示すとは限らないので、「ファイル形式の選び方」などのリンクにし、見れば分かる最初の2行は不要、と著者）。
- **Airbnb**：「クリーニング料金：ホストが清掃費用として1回だけ請求」「サービス料：プラットフォームを運営し、24時間サポートするための料金」。料金が何に使われるかがきちんと説明され、安心する。計算結果は算出方法を明示（1泊ごとの内訳、平均は四捨五入）。**情報の透明性は大いに安心感を与える。**
- **Golan Telecom**（イスラエルの携帯会社）：「ナンバーシークエンスとは、複数の回線を連番で購入できるサービスです」。本気で売りたいなら「複数の SIM カードを連番で入手しましょう」と行動を促す言い方に。
- **Target**：「ギフトナウとは？」のテキストリンク。**Typeform**：質問の種類ごとに文例をツールチップで（「例：チーズの臭さ、0〜5でどのくらいが好き？」）。

### 疑問2：どんな機能？（p.200、写真がぶれて本文は読めず）
- 事例は YouTube の自動再生（「自動再生をオンにすると、おすすめ動画が自動で次に再生されます」）、eBay「このセラーを保存」。
- **Toshle**（家計管理アプリ）：ユーモアたっぷりのモンスター。ユーモアが苦手な人は「ポリティカリーコレクトなモンスター」をオンにすると大人しくなる。
- **Notica**：「高解像度をオンにすると元画像が2048pxで保存。オフにすると容量は節約できるが1024pxに」。オン/オフの結果を説明。
- **WhatsApp**：「インカミング・メディアを保存：受信した画像と動画を自動的にカメラロールに保存します」。スイッチにシンプルなラベル＋その下に何をする機能か。

### 疑問3：その情報はどこに？（p.202〜203）
- 特殊な情報（免許の区分、料金の顧客番号など）を求めるときは、入力欄のすぐ隣に、どこを探せば見つかるかを。できれば画像で、位置をハイライト。
- ダッシュやスラッシュを含む値は、そのまま入れるのか、どんな形式かを明記（数字だけ入れればよい欄にする方法も）。
- **HP**：「製品名/製品番号はどこ？」のリンク→ノートPCの底面の写真。ラベルとプレースホルダー（例：Photosmart A636…）がうまく働いているので、指示は不要で、リンクも短文で十分。
- **Monday.com**：「ID とは？ そしてその情報はどこに？ ID は各ボードの固有のシリアル番号で、URL の一番最後にあります」＋拡大図。

### 余計な言葉を削る（p.203）
- 「メーカー：自動車メーカー名を選ぶ／製造年：車の製造年を選ぶ」→ラベルだけ（メーカー／製造年／モデル）。「ログイン：以下の詳しい情報を入力してください（必須項目）／ユーザー名を入力／パスワードを入力」→「ログイン／ユーザー名／パスワード」。ただしサイトの入り口のタイトルは、もう少し歓迎の意を込める。

### 疑問4：どう使えばよい？（p.204〜）
- UX の理論ではインターフェイスは説明不要であるべきで、言葉は最後の手段。でもユーザーは本当に自力で全部理解できるのか？ これも知識の呪い。説明が必要かを判断する一番の方法は**ユーザビリティテスト**。
- **説明の必要がない箇所**：入力欄、ボタン、プルダウン、!や?のアイコン、リンク、アスタリスク、ラジオボタン、チェックボックス。入力欄はラベル「メールアドレス」だけで、「あなたのメールアドレスを入力してください」は不要。ボタンに「クリック」も不要。**OkCupid**（ダイエット方法／たばこ／酒のプルダウン、説明なし）。

### TIP22 複数の項目を選択できます（p.205）
- ラジオボタンは1つ、チェックボックスは複数。けれど誰もがそれを知っているとは限らない。複数選べるときは、そう伝える。

**Soto への示唆：**
- **知識の呪いが一番効くのは Soto 自身の用語**。私たちには当たり前でも、初めての人には分からない言葉がサイトにある：「Soto Map」「Soto Pass」（機能の造語）、「先行登録」「先行体験」「予約金」、端末関連なら「eSIM」「2台目」「AOSP／GMS」（サイトに出すなら）。Monday.com のように、名前のすぐそばで**何を意味し、何に役立つか**を一言で。Soto Pass は今「外に出たくなる仕掛け」と説明がある。良い状態。
- 「先行登録」と「先行体験」は名前が似ていて、違いが分かりにくい。それぞれ一言で：「先行登録：発売の案内を受け取る（無料）」「先行体験：試作機を1週間ほど使ってもらう（希望者のみ）」※実際の運用どおりに。
- 料金ページ（plans）：Airbnb の例どおり、月額や端末代の**内訳と、それが何に使われるか**を書くと安心感が大きい。料金が決まったら、eSIM の月額に何が含まれるか（通信量、通話、サポート）を ? かリンクで。※料金は未決定なので、決まってから。
- 「LINE は使えるか」は最多の疑問になるはず（顧客サポート担当者の方法）。お問い合わせで多い質問を記録し、FAQ と、その疑問が湧く場所（製品説明の近く）に答えを置く。
- 地域のプルダウンや先行体験のチェックは説明不要（ラベルだけで十分）。説明が要るのは「なぜ聞くか」「何が起きるか」だけ（第14章のメモどおり）。
- 端末の設定画面を作るなら WhatsApp / Notica 型：スイッチにシンプルなラベル＋下に「オンにすると何が起きるか」を一行。たとえば集中モードやメッセージ転送のスイッチ。

### 説明の必要がある箇所（p.206〜207）
- 不要な例：「以下のボタンをクリックしてソーシャルアカウントでログイン」＋［Facebook でサインイン］［Google でサインイン］。必要な情報はボタン自体に書いてある。
- 独自のインターフェイスや、比較的新しいタイプの操作なら、適切な場所に簡潔で的確な指示を。
- **Instagram**「音声の再生は動画をタップ」。導入当初は全動画に表示。操作が普及したら、使い方を理解していないと推測される場面（音声オフのまま音量を上げようとしたとき）だけ表示に変えた。
- **Typeform**：「ブロックを追加して質問を作成」＋矢印で独自UIを説明。

### TIP23 ユーザーが自分で自分を守れるように（p.207）
- 途中終了、新しいウインドウ、入力内容を全部消すなど、使い方を間違えると本人やプロセスに問題が降りかかる操作は、説明しなくても分かりそうでも、目に付く場所に分かりやすく。影響の大きい操作ほど説明が重要。

### TIP24 気持ちの良い言い方を――指示は指令ではない（p.207）
- 簡潔で分かりやすく、でも命令口調は避ける。感じの良い、サービス志向の言葉で。ブランド次第で多少のユーモアも（分かりやすさは犠牲にしない）。
- **WeTransfer**：ファイルをドラッグすると「Drop it like it's hot（このウインドウ内ならどこにでもドロップできます）」。

## 23. 第16章 不安や懸念を軽減する（p.208〜221、途中まで）

章の内容：対応が必要な7種のよくある不安や懸念。

### 気付かないふりをしても、消えてはくれない（p.209）
- ユーザーが信頼してくれないのには、もっともな理由が多数ある：売り付けたいだけかも、無料は今だけかも、メールを教えたらスパムが殺到するかも、大企業の情報漏えいのニュース、余計なアイテムまでダウンロードされた話。ネットで生き延びるには常に警戒が必要。
- まだよく知らないブランドを信頼する理由はない。**信頼は努力の末に獲得するもの**。インターフェイスのすべてを、心情面と実用面の双方から、真にユーザーの立場に立って作る。そのうえで信頼に足ることを示す。不安には理由があるので**見て見ぬふりをしない**。心情を理解し尊重していることを示し、任せてほしいと伝える。

### 不安#1：メールアドレスを教えること（p.210〜211）
- a. **大量に送られてくるのでは？** →配信頻度が適正だと確実に伝える。さらに**クリックひとつでいつでも解約できる**と明記。
- b. **第三者に提供され、スパムが届くのでは？** →他者に提供しないと約束し、個人情報の保護はあなた自身にとっても重要だと伝える。
- **Metro MSP**：「重要！ 私たちは、あなたと同じく（またはあなた以上に！）スパムは一切お断りです。メールアドレスや連絡先情報の貸与、共有、悪用は決してしないと約束します」。
- **Sugru**（支払いフォームのメルマガのチェック横）：「メールマガジンは月に2回の目安で発行します。最新情報や特別オファーなど。スパムは決して送りません。約束します」。
- **Rounds**（プッシュ通知の許可）：「はい、もうひとつポップアップです！ 通話をつなぐために、プッシュ通知の許可が必要です。情報は適正に取り扱うことを約束します！」。

### 不安#2：特別な個人情報を提供すること（p.211〜216）
- 生年月日、電話番号、性別、住所への警戒心が高まっている。頼まれると懐疑的になり「何のために必要なのか」と問わずにいられない。その問いにきちんと答える。
  - a. **入力必須なら**：必要な理由を説明し、個人情報の保護を保証する。
  - b. **任意なら**：その情報が何に役立ち、本人にどんな利益をもたらすかを説明する。
- **Tesco**（電話番号）：「ご注文に関する問い合わせが必要な場合のみ、この番号に連絡します」。目的の説明と、他の目的に使わない約束を兼ねる。
- **Monday.com**（電話・任意）：「即時のサポートを提供する目的にのみ使用します。スパムは一切ありません！」。
- **Claire's**：「個人情報を共有または譲渡することはありません」。電話番号「なぜこの情報が必要か？ 配送業者が配達時間を相談する場合に必要です」（著者：もっと短く「配達時にのみ必要です。それ以外には使われません」）。生年月日「13歳以上か確認するためです。また誕生日には特典を」（理由と利益の両方）。
- **American Eagle**：電話番号はカードの登録番号と一致が必要（エラー防止）＋「大丈夫です、この番号は決して誰とも共有しません」。
- **Europcar**：「年齢を確認したうえで、利用料金を見積もります。若年ドライバーには追加料金」。
- **Pinterest**：性別を尋ねる理由（ぴったりのアイデアを見つけるため）＋カスタムジェンダーの欄。**Vimeo**：性別でなく代名詞（she/her、he/him、they/them、言いたくない）＋「あなたに相応しい代名詞で呼び掛けたいので」。
- **boohoo**（任意）：生年月日「誕生日特典をお送りします」、性別「お似合いのエクスペリエンスに」。

### 不安#3：ソーシャルメディアのアカウントを利用する会員登録（p.217、写真ぶれ）
- 約束すること：a. **本人の名前で投稿することはない** b. **情報を第三者に渡すことはない**。ほとんどのサイトが a だけ。b も大変重要。
- **Munchery**「自動投稿は一切なし」、**eHarmony**「決して、絶対に、何も投稿しません」（秘密を守るサイトでは二重に重要）、**Switch**「あなたに代わって投稿することは決してありません」。

### 不安#4：決済のセキュリティ（p.218〜219）
- 最大の気掛かりはカード情報が安全に守られるか。決済ページへのボタンや支払いフォームそのものにメッセージを入れ、事前にすくい上げて解消する。
- **Airbnb**：カード番号欄に鍵アイコン＋「クレジットカード情報は安心決済システムで暗号化されます」。**Europcar**：「乗車時に支払い」＋「セキュアなサーバー、すべて暗号化」。**Macy's**：フォーム最上部「安心決済」。**H&M**「すべてのデータは暗号化されます」。**Marks & Spencer**「セキュア決済」、**Roxy**「安心決済」（ボタン）。

### TIP25 送料を払うのは誰？（p.219）
- 誰が負担するか、いくらか、期待に添わなかったら返品方法と返品送料は。購入プロセスの最初の段階で、すべての疑問にはっきり答える。

### 不安#5：無料トライアル（p.220）
- 一番の不安は、期間終了後すぐ課金されるのでは、という点。心配はないとはっきり伝える。登録の冒頭で「カード情報は不要（つまり課金はあり得ない）」と約束。カード情報が必要なら、確実に許可しない限り決して請求しないと約束。
- **Poptin**「入力フォームは使いません、クレジットカードは要りません」、**Spotify**「豊富な楽曲。クレジットカード不要」、**Google Cloud**「無料期間終了後のオートチャージはなし。カード情報はロボットでないことの確認のため。手動で有料に更新しない限り課金されません」。

### 不安#6：入力値や設定の内容（p.221、写真ぶれ）
- 何かを真剣に考えなければならないと分かると、中断して後回しにする人がいる。**後からいつでも変更できる**と説明すれば、余計な心配なく進める。
- **Udemy**「仮称にしませんか？ まだ良い名前が思い付かなくても大丈夫、後で変更できます」、**Tumblr**（ユーザー名の候補を提案＋「いつでも変更できます」）。

**Soto への示唆：**
- 不安#1 は先行登録そのもの。答えるべき2点は**頻度**と**第三者に渡さないこと**＋**ワンクリックで解除**。サイトには「月1回の開発レター」「いつでも配信を止めたり削除したりできます」があるが、①折りたたみの中 ②「第三者に渡さない」の一文がフォーム付近にない（プライバシーポリシー内にはあるか要確認）。フォームの近く一行候補（事実どおりなら）：「月1回のお便りだけ。ほかの会社には渡しません。いつでも1クリックで止められます。」
- 「スパム」という言葉は Soto の静かなトーンに合わないので、「送りすぎません」「ほかには使いません」の言い方で。
- 不安#2：地域の欄（任意）は「何に役立つか」を一言（boohoo 型）。お問い合わせの名前・メールは「お返事のためだけに使います」が既にある＝Tesco 型で良い状態。
- 不安#5：Soto は eSIM の月額課金。将来の申込では「端末を受け取って開通するまで月額は発生しません」「解約は◯◯からいつでも」のように、**いつから課金されるか・どう止めるか**を最初にはっきり書く。2台目として試す人ほど、ここが最大の不安になる。※料金・解約条件は未定なので、決まってから。予約金を取る場合も、返金条件をボタンの近くに（terms ページの内容と一致させる）。
- TIP25：shop で端末を売るなら、送料・返品送料を最初の段階で。
- 不安#6：端末の初期設定（名前、通知、アプリの選択）は「あとでいつでも変えられます」を添えると、迷わず進める。
- TIP24：Soto の指示文は「〜してください」の連続にせず、「〜できます」「〜でどうぞ」のような感じの良い言い方で。

### 不安#6 の続き（p.222）
- **Typeform**：「テンプレートのカスタマイズについて、ご希望をお伝えください。いつでも戻って変更できます」。ニーズは時間とともに変わる、という認識。

### TIP26 努力は報われる！（p.222）
- 手間のかかる作業（写真のアップロード、アドオンのインストール、自己紹介を書く）は、任意でも必須でも、多くの人が飛ばそうとする。
- なぜその作業が本人のためになるか、どんな利益があるかを言葉に。サイトに来た元々の理由に立ち返ってもらい、この一手間が目標に近づけると伝える。
- **Facebook**：「あなたの最近の写真を選んでください。写真を見れば、知り合いは間違いなくあなただと分かり、連絡を取ることができます」＋［スキップ］［OK］。つながり合うことこそ使う理由。

### 不安#7：ダウンロードまたはインストール（p.223）
- 最大の不安は、目的のもの以外（ウイルス、スパイウェア、不要なツールバー）が付いてくること。ウイルスフリーを保証し、目的以外は入らないと伝える。
- **Download.com**「セキュアなダウンロード。このファイルをスキャンし、ウイルスやスパイウェアが含まれないことを確認しました」。**Rounds**「100%フリー。スパイウェアなし、アドウェアなし、ウイルスなし」。

**Soto への示唆（追加）：**
- TIP26 は端末の初期設定にそのまま使える。たとえば「緊急連絡先を登録」「Soto Map に最初の場所を記録」のように飛ばされやすい手順には、その一手間で何が得られるかを一行で（「家族からの電話だけは、集中モード中でも鳴ります」など、実際の機能どおりに）。スキップも選べるようにし、責めない。
- 不安#7：端末に入れるアプリ（LINE 等）を案内するときは「ほかのアプリは一緒に入りません」「SNS は入りません」と明言できる。Soto の「入っていないこと」は、ここでは安心材料として働く。

## 24. 第17章 エラーやトラブルを防止する（p.224〜235）

章の内容：マイクロコピーで簡単に予防できる5つの問題。

### 5つの予防策（p.225）
- エラーメッセージの役割は立て直すことだが、最初からエラーを防げるほうが良いに決まっている。設計する側には全体が見え、システムが受け付ける値とエラーになる値が分かり、次に何が起きるか予想できる。だから、何をすべきか伝え、エラーやトラブルに巻き込まれないよう**予防する責任はあなたにある**。
- やるべきことはひとつ：フォームとプロセス全体を再点検し、弱点を見つけ、ほころびが生じそうな箇所に適切な助言を書き添える。

### 予防策#1：入力必須項目（p.226〜227）
- もっとも不必要で見せるべきでないのが「この欄は必須項目です」というエラー。必須という事実を、はっきり、分かりやすく、間違える余地なく、命令口調を避けて伝える。
- アスタリスクでうまく処理できる。全部の欄に付いていてもかまわない（**Musketeer**：全欄に＊。「＊は必須」の一言さえ不要、見ればわかる）。
- アスタリスクを目障りに思うという調査もある。その場合はフォーム最上部に「すべて必須」と明記し、必須でない項目だけに「任意」と書き添える方法も（さらに、それを任意にしておく必要が本当にあるか問い直す。情報は少ないほど完了率は高まる）。
- **Walmart**：アスタリスク＋「（任意）」の組み合わせ。**Marks & Spencer**：ボタンにマウスオーバーした時点で「色またはサイズを選んでください」と出し、エラーを防ぐ。
- いずれにしても、曖昧な部分を一切残さない。決めたルールをユーザーが自力で読み解く状況は避ける。

### 予防策#2：記号や特定の書式（p.228〜229）
- ダッシュ、スラッシュ、文字と数字の組み合わせ、何通りも書き方がある値（日付、電話番号）は、記号も打つべきか、どの書式か判断がつかない。気付かずに自分流で入力する人もいる。
- 理想は、どんな書き方でもシステムが受け付けること。それなら説明は要らない。
- 特定の書き方しか受け付けないなら、**入力を始める前に**正しい書き方を明示する。
- **The Idle Man**：日・月・年を別々の欄に（DD／MM／YYYY）。インターフェイス自体で解決。**PayPal**：フォーカスすると下に「2桁（スペースなし）」「4〜9桁の番号。不明な場合は取引銀行にお問い合わせください」、有効期限の欄に mm/yy。

### 予防策#3：サイズや範囲、長さの制限（p.230）
- まず、受け付けない値の入力を防ぐ UX 手法がないか確認（カレンダーで日付をグレーアウト、上限で入力を止める）。
- それでも制限はきちんと明記する。**制限をプレースホルダーに入れない**（入力を始めると消える）。
- **OkCupid**：「写真は400×400px以上、あなたが写っているものを。ただし挑発的な写真は控えて！」。**Foodgawker**：欄の外に残り文字数をカウントダウン。

### 予防策#4：パスワード（p.231〜232）
- 要点以外は省いて言葉を減らす。さっと目を通すだけで理解できる書き方を。
- **American Eagle**「6〜15文字＋数字」。**ユニクロ**（文章で書いているので箇条書きの方が見やすいのでは、と著者）。**Yes**：フォーカスでツールチップに条件を並べ、満たした項目にチェックマーク。上出来。

### 予防策#5：実世界で発生する問題（p.233〜235）
- UX はデジタルから離れた時点で終わらない。接点がある限り続く。証明書の発行、文書の印刷、配送品の受け取りなど、実世界の作業をひとつずつ検証し、問題が起きる可能性がないかチェック。
- 力の及ばない問題でも、可能性を伝えておけば、納得し、ユーザーの立場であらゆる物事に目を配っていると実感してくれる。
- **Belle and Sue**：「ご注文の商品は、当社営業日の9:00〜17:00に配送されます。勤務先への配送をご希望の場合は、勤務先の住所をお知らせください」。
- **QR Code Generator**：余白なしを選んだ人に「読み取りには白い余白が必要。余白なしなら明るい背景に印刷を」。サイトを離れた後の使われ方を調査した結果。
- **Marmalade Market**：一点物・手作り品の注文で、プレースホルダーで「サイズ、色、受け取れる時間帯など、できるだけ詳しく」と提案。
- **Pekin Zahala**（テルアビブのレストラン）：パクチーとピーナッツを含む料理には「注意！ このメニューにはパクチーとピーナッツが含まれています。食べられますか？」＋選択肢（「はい、OK です」「パクチーは OK、ピーナッツは抜いて」「ああ、教えてくれてありがとう。どちらもなしで！」）。プロセスを全体として捉えるホリスティック思考。状況を明るく楽しむ言い方で、すべての人に良い体験を。

**Soto への示唆：**
- サイトのフォームは必須の示し方が2通りある：お問い合わせは「（必須）」「（任意）」を両方表示、先行登録は「任意」だけを表示。どちらも分かりやすいが、本の「一貫性」と「任意は本当に要るか」の観点で揃えるなら、**任意の項目だけに「（任意）」**の方式に統一し、地域の欄（任意）が本当に必要かも見直す。※変更はフォームの実装確認後。
- 予防策#5 が Soto にいちばん大きい。端末は実世界で使うもの。購入後に起きうる問題を一つずつ洗い出し、申込みや同梱の案内で先に伝える：
  - eSIM の開通（Wi-Fi が要るか、今の番号を移せるか＝MNP、開通までの時間）
  - LINE の引き継ぎ（1台目のアカウントとの関係、2台目として使うときの制約）
  - 配送（受け取れる時間帯、不在時）
  - 充電器が同梱か
  ※どれも仕様が決まってから、事実だけを書く。分からない段階で約束しない。
- Pekin Zahala 型の「先に聞いておく」は、端末の注文時に使える：「LINE を使いますか？」「今の電話番号をそのまま使いますか？」のように、後で困りそうなことを選択肢で先に確認する。

## 25. 第18章 マイクロコピーとアクセシビリティ（p.236〜251）

章の内容：アクセシブルなマイクロコピーを書くための7つのガイドライン。執筆はロテム・ピンハイム（AUX＝Accessible User Experience の専門家）。

### 万人のためのマイクロコピー（p.237）
- 有益な体験とフラストレーションの違いは紙一重。決めるのは、必要な箇所に出る、たったひとつの言葉かもしれない。**画面を見るのが困難な人、まったく見えない人**のためのマイクロコピーでは、その差が倍に膨らむ。
- 7つのガイドラインに従えば必ず役立つものが書ける。ライターだけでなく、プロダクトマネージャー、UX デザイナー、ビジュアルデザイナー、開発担当者も理解すべき。

### スクリーンリーダーで読み上げるとどうなるか？（p.237）
- 視覚障害者の多くはスクリーンリーダーを使い、マウスではなくキーボードで操作する。タブや矢印キーで次の要素へ。順番は上から下、左から右（開発時の優先順位があればそれ）。リンク、ボタン、画像を識別して読み上げる。
- だから利用者は**画面全体の像を知らず、近くの要素同士の位置関係も分からない**。個々の要素を一つずつ認識するだけ。

**Soto への示唆：**
- サイトは、トップのメール欄にも読み上げ用のラベル（画面には見えない「メールアドレス」）が付いている。ボタンの矢印アイコンは読み上げ対象外（aria-hidden）。良い状態。
- 位置関係が分からない＝「下のボタンを押してください」「右の表」のような書き方は避ける。ボタンの文言だけで何をするか分かるようにする（第11章の「得るもの」型は、ここでも有利）。
- 続きのガイドライン7つが届いたら、サイト全体（画像の代替テキスト、リンクの文言「こちら」など）を点検する。

### 7つのガイドライン（p.238〜249）
1. **上から下、左から右の順で考える。** 読み上げはこの順（戻るときは逆）。タスクを助け、エラーを防ぐ言葉は**実際の行動より前に**読まれるよう置く。パスワード欄の下に条件を書くと、設定し終えてから条件を知り、やり直しになる。誕生日の欄の後ろの ? も届かない。配置順は **ラベル ＞ 説明文 ＞ 入力欄**。
   - Facebook（言語の欄の前に説明）、Walmart（CVV の ? をラベルの直後に）。
   - 開発者メモ：フォーカス順が正しければ配置は自由だが、キーボード操作の人や認知機能障害のある人のため、見た目の位置関係と文章の流れを一致させる（スコット・ピンクル）。
   - **どんなマイクロコピーも、確認ボタンより後ろに置かない。** 視覚障害の同僚が確認ボタンを5回押しても反応せず、ボタンの下に「条件に同意する」のチェックとエラーが出ていた。見えず、フォーカスも移らず、結局実店舗へ行った。
   - キャプチャがリセットボタンの下にあると、押すまで存在が分からない。エラー「このフォームを送信できるのは人間だけです」も、どこで何が問題かを伝えない。
   - まとめ：行動の完了に必要な情報は**すべて事前に**、ラベルの上か右隣に。
2. **趣向を凝らした表現でも、分かりやすさを犠牲にしない。** 読み上げだけで、今どこにいて次に何が起きるか分かるか。スイミングスクールの読み込み「57% 飛び込み台まで、あと少し…」→「読み込み中です：飛び込み台まで、あと少し…」と一言足す。通知が空の「SHHH! ここはとても静か」は、画像の文字が読めないと「とても静か」しか届かない。エンプティステートや404は、画像や婉曲表現だけで終わらせない（「お探しのページは見つかりません」「新しいお知らせはありません」と言葉で言い、その先に進む方法を示す）。
   - 会員登録ページ：「この出会いを次の段階へと進めましょう」は、ボイスに合っていても、会員登録ページだと言葉で伝えていない。読み上げの利用者はメール欄に来ても、なぜ入力するのか分からない。ここが登録ページだと書き、登録の理由を添える（見える人にも有効、一石二鳥）。
   - 成功・エラーメッセージは特に。目を閉じて声に出して読んで、何が理解できるか。緑のVサインや赤い囲みが見えなくても、完了したか／どこに問題があり、どう抜け出すかが分かるか。
3. **すべてのアイコンや画像に代替テキストを。** 画像が読み込まれないときにも表示されるので全員に有用。ただし単なるストックフォトなど理解を助けない装飾には付けない（情報過多で煩雑になる。Amazon の商品写真は横に説明があるので不要）。言葉のないアイコン（歯車、家）には必ず。i ! ? のアイコンにも、リンク先に何があるかを言葉で（「パスワードの設定方法と詳細情報」）。
   - 注意#1：代替テキストに趣向を凝らした表現は不向き。誤解の余地のない言い方で。
   - 注意#2：頻繁に参照されるツールチップは、消えない表示に切り替えたほうがよい。
   - 絵文字には既定の代替テキストがある。どう読まれるか知っておく（モリー・バーク "What do Emojis look like?!"）。
4. **リンクやボタンには「もっと見る」ではなく説明的な言葉を。** キーボード操作では見出しの間だけ、リンクとボタンの間だけを移動できる。「投稿を見る」が3回続くと何も分からない→「卒業式の装い」「成功願望を手放そう」「ギフトカタログを表示」。移動先の情報を少し書いておくのは誰にとっても有益。
5. **すべてのマイクロコピーは画像文字ではなく通常テキストで。** 画像化したボタン、アイコンと一体の文字、404の大きな画像の中の文字は読み上げられない。Spotify の下部ナビ（ホーム、検索、あなたのライブラリ）はテキストか適切な代替テキストで。
6. **リーダビリティ：ページ上に持続的に、高コントラストで。** 指示・ヒント・注意書きは、いつでも確認できるよう表示し続けるか、繰り返し読めるツールチップに。フォーカスで消えるプレースホルダーは、見える人にも使いづらい。移動するプレースホルダーは読み上げ設定はできても、認知機能障害の人を混乱させうる。スペースに余裕があれば入力欄の外にラベル。狭くて中に置くなら、フォーカス後も文字が残るように。
   - 高コントラスト：弱視や識字障害の人のため、すべてのマイクロコピーを背景に対して高コントラストで。読みやすさは全員の得。プレースホルダーに重要な情報があるなら、色を薄くしすぎない。そもそも本当に要る内容か確かめ、不要なら削除（「例：ノラ」「都市名を入力」は低コントラストより不要なことが問題）。Tesco：ラベルは外に固定、入力欄も高コントラスト。
7. **シンプル・イズ・ベスト。** 読者は簡単に理解できると想定しがちだが、略語、頭字語、駄じゃれ、言葉遊びは理解できない人や努力を要する人が少なくない。「マジックワード（＝パスワード）」「マジックワードをまだ持っていません（＝アカウントがない）」は誰のためにもならない。ライトブルーの入力欄の低コントラストも問題。

### 私的メモ（執筆者）（p.249）
- この原則を学んで、どの程度凝った言い回しをしてよいかの答えが出た。書くテキストがスクリーンリーダーの利用者や認知機能障害のある人に読まれることを想像すれば、どこで線を引くべきかすぐ分かる。言葉はどんどんシンプルに、分かりやすくなった。ここぞという場面でのみ、気の利いた言い方をする。
- 彩り豊かで個性あふれるマイクロコピーは続けよう。ただし「**ここに書いた言葉はすべての人に理解してもらえるだろうか**」と自問することを忘れずに。

### Cut out & Keep：フォーム入力完了率を上げるチェックリスト（p.250〜251、一部）
- ライティングの前に：1. 入力を完了するだけの十分な理由があるか（フォーム最上部かリンク元のページで、行動の真の価値を約束） 2. マイクロコピーが多すぎないか（説明不要な所まで説明、言葉が多すぎ、UI/UX が不完全なら UX デザイナーに持ち帰る） 3. 足りなくないか（重要な説明や確認の一言を省いていないか、必要な指示がツールチップに隠れていないか）。
- 分かりやすさ：4. 会話体（使い慣れた言葉で直接語りかける、簡潔で率直） 5. 操作する要素のラベルを個別にチェック（言い換えられる専門用語、一部でのみ通じる言葉、曖昧で紛らわしい言葉→簡単な言葉に替えるか説明を加える） 6. 複数の選択肢（即座に理解できる、名称が内容を表す、違いが明確、複数選択可なら伝える） 7. プレースホルダー（入力中に確認したい情報は入れない、ラベルの繰り返しは避ける、高コントラスト） 8. ツールチップ（定位置に表示し続けたい重要情報は入れない、フォーカスで自動表示は1回限りかごく稀な項目向き）。
- スムーズな操作：9. エラーを見飽きさせない（どんな値・書式なら受け付けるかを開発担当に確認し、エラーになる値の注意を入力欄の近くに前もって） 10. 必須／任意の表示（アスタリスクか「任意」。全部必須なら目立つようにそう書くか、全欄に記号） 11. オープンクエスチョン（書き出しの文例でテーマを絞る、文字数制限は明記、カウンターも一案） 12. スイッチとチェックボックス（オン／オフを選ぶのに必要な情報をすべて、言外の意味合いも） 13. 添付ファイル（種類やサイズの制約は事前に） 14. エラーメッセージ（起こり得るすべてのエラーのシナリオを開発チームから受け取っているか、原則に従ったか）。
- 不安への対応：15. 個人情報（必須なら理由、任意なら何を得るか） 16. 特殊な情報（どこを探せばよいか） 17. セキュリティ（支払いは成功した時点ではっきり伝える、情報は保護され外部に漏れないと伝える） 18. 入力値の変更（後から変えられるなら明記して悩まず進めてもらう。変えられないなら後悔しないよう事前に注意）。
- クリックすれば終わりではない：19. 待ち時間（送信から成功メッセージまでの時間をやり過ごせるメッセージ） 20. 成功メッセージ（送信直後に何を見るか。成功を心から喜び、努力を讃え、良質な体験を締めくくれているか）。

**Soto への示唆（サイトを確認して）：**
- 良い点：トップのメール欄にも読み上げ用ラベル、ボタン内の矢印アイコンは読み上げ対象外、登録完了カードは role="status"、サイト内に「もっと見る」「こちら」「詳しく」のような曖昧なリンク文言は見当たらない。
- 直したい点：
  - **プレースホルダーの色が薄い**（styles.css：rgba(31,30,28,.45)、背景 #f4f2ec に対して概算でコントラスト約3:1。本文の目安 4.5:1 に届かない可能性）。トップのフォームはプレースホルダー「メールアドレス」がラベル代わりなので、ここは濃くするか、見えるラベルを置く。※実測してから直す。
  - 先行登録フォームで、「登録すると、プライバシーポリシーに同意したものとします」と「登録について」の折りたたみが**ボタンより後ろ**にある。読み上げの利用者は押した後に知る。本の原則「確認ボタンより後ろに置かない」に照らすと、同意の一文と、障壁への答え（無料・月1回・いつでも止められる）はボタンの**前**に置くのが正しい。これまでの章の「ボタンのすぐ近くに一行」は、**ボタンの直前**に置く形で実装する。
  - 「Soto Map」「Soto Pass」のような造語や英語のタブ名は、読み上げでも意味が分かるよう、近くに日本語の一言を（第15章のメモと同じ）。
  - 404ページを作るとき（第12章メモ）、画像の中に文字を入れず、「このページは見つかりませんでした」を通常テキストで。
  - 端末UI：「新しい知らせはありません。外の時間をどうぞ」のような空の画面は、気の利いた後半より先に、事実（知らせはない）を言葉で言う順番にする（ガイドライン2）。
- 執筆者の私的メモは Soto の線引きの基準になる：**基本はシンプル、ここぞという場面でだけ、一言の工夫**。

## 26. 第19章 複雑なシステムのためのマイクロコピー（p.254〜269）

章の内容：複雑なシステムの定義／その中でのマイクロコピーの価値／なぜボイス＆トーンのデザインが必要か。

### 複雑なシステムとは（p.255〜256）
- 互いに関連し合う多数のコンポーネントからなり、操作がリニアでない（入口から入って出口から出る直線ではない）。何度もアクセスし、複合的に連係する要素を扱う。
- 種類：1. エキスパートシステム（専門家向け：遺伝子研究のログ、3D CAD のクレオ・パラメトリック、自動車整備の診断） 2. イントラシステム（給与、カルテ、顧客管理＝Salesforce など） 3. 一般ユーザー向けの機能的システム（ワープロ、銀行口座管理。Word も複雑なシステム）。

### 使われ方とマイクロコピー（p.257〜258）
- 複雑なシステムは総称で、NASA 向けも、24歳のシフトリーダーのコールセンター管理も、医療秘書向けもある。個々のシステムはターゲットや目的に応じた独自のボイス＆トーンを持つ。
- **専門性と実用性**：一般向けは専門用語を言い換えるのが鉄則だが、ここでは専門用語を使うことこそ必要。A. ユーザビリティ（現場で使い慣れた用語のほうが簡単） B. 信頼（専門家が専門家のために作ったと伝わり、システムを信頼して専門性を委ねてくれる）。
- ただし**専門性に優れる＝格調高く仰々しい、ではない**。目指すのはシンプルで正確な言葉。理由：①多くは日々の忙しい業務の一部なので、短く、ダイレクトに、明確に、一瞬で理解できるように ②古い辞書にしかないような言葉、時代遅れの堅苦しい言葉は事態を厄介にするだけ。「格調高い」言葉は専門性の証ではなく、形式にとらわれた考え方の表れ。**博士論文の言葉ではなく、人と話すときの言葉で書く** ③理解のレベルが人によって違う（初心者もエキスパートもいる）。
- 例：**イスラエル司法省**「お知らせします。入力されたID番号のデータはすでに存在します。それはつまり、あなたが過去に…その結果、確認ボタンを…」→「あなたのID番号はすでに存在します。ログインするか、パスワードを復元してください」。ごく普通の日常的な言葉でも専門的なテーマは扱え、アクセシビリティも向上。**RealMatch**「広告到達の動向と具体例」→「あなたの広告は今どこに？」。**NICE**（削除確認を短く、ボタンも行動そのものに）。

### ユーザーに手を差し伸べる（p.260〜263）
- 「ユーザーは聡明だから」「説明書を読めば」「サポートデスクに」で済ませず、マイクロコピーで積極的にサポートする。
1. **タイトル**：メニュー、ラベル、機能名、グラフタイトル、カテゴリー名、表の見出しはシンプルで誤解の余地なく。
2. **プレースホルダーとヒント**：入力を始めたら読み返す必要のない簡単な説明だけ。入力欄の上の短いメッセージやツールチップも。
3. **ツールチップ**：ラベルのすぐ後ろに i アイコン。短くシンプルに、ただしヘルプデスクや説明書に行かずに済むよう必要な情報は漏れなく（複雑なシステムでは長くなっても問題ない）。RealMatch の「ステータス」：意味＋全種類（有効、期限切れ、承認待ち、下書き、却下、完了）。「サイトごとのクリック数を比較し、キャンペーン戦略をさらに上手に管理しましょう」＝機能の利点を伝える。
4. **ユーザーガイドの参照先を明示**：長文が必要なら、難しいことへの理解を示し、ガイドのどこを読むかを明示し、リンクを。
5. **エラーメッセージ**：複雑なシステムでは一層重要。問題を手短に、解決方法を明示、委縮させない親しみやすい言葉、不安をあおらず落ち着いて。**極めて重要：システムや開発者の視点ではなく、ユーザーの視点から問題を捉える**（何をしようとしていたか、どこで不具合が、どう直すか。技術と専門性の両方の理解が必要）。PTC Agile Works：「スプリントは、ストーリーが未完だと終了できません」＋OK →「一部のストーリーが未完です：S-8（進行中）。現在のスプリントを終了する前に、未完のストーリーを次のスプリントに送りますか？ はい／いいえ」。仕組みの説明から、ユーザーへの選択肢の提示へ。
6. **エンプティステート**：システムの働きを知ってもらう好機。今できること、やるべきこと、本来何を提供するはずかを伝え、先に進む方法を。RealMatch「データが入手できません」→「すぐに戻ってきてください。最適な予測のためにデータを集めています。公開から最大7日かかります」、「表示する広告がありません」→「現在アクティブな広告はありません。広告を有効にすると、ここで成果を確認できます」。人間らしくフレンドリーでも専門性は損なわれず、むしろ一層専門性が感じられ、情報も正確。

### TIP27 また?!（p.261）
- 毎日、一日に何度もアクセスする人もいる。頻繁に実行するタスクでは笑いを控える。1回目は笑ってもらえても、3回目は？ 30回目は？

### 30年間、ずっとこれでやっています！（p.262〜）
- 30年続くシステムは、ユーザーが使い方に慣れ親しんでいる一方、仕事以外で使う現代的なインターフェイスとのギャップが広がる。翌朝仕事に戻るとタイムトンネルで開発当時へ。
- 一気に全部のボイス＆トーンを変えるのは不可能。新機能だけ変えると一貫しない部分ができる。どうするか：新機能はすべて時代に即したマイクロコピーに。旧機能は何度もバージョンアップする中で刷新。新旧に同種の要素がある場合は、ユーザーが関連付けられるよう調整し、ギャップを解消（専門用語は変わらないので、さほど大掛かりにはならない）。
- **変更する前に、総合的なボイス＆トーンのスタイルガイドを完成させ、残すものと変えるものを決めておく**ことを強く勧める。組織内の多数の部署との連携が要るので、変化を受け入れる機運も高まる（PTC のシャニ・ポランスキ）。

**Soto への示唆：**
- Soto の端末は「一般ユーザー向け」だが、2台目として毎日何度も触る道具。TIP27 がそのまま当てはまる：通知、ロック解除、毎日の画面には冗談を入れない。工夫は初回や、まれな場面だけ（第18章の線引きと同じ）。
- 「格調高い言葉は専門性の証ではない」は、eSIM・MNP・APN など通信の専門用語にも。必要な場面では正しい用語を使いつつ、文は人と話すときの言葉で。司法省の例のように「〜ということになります」を重ねず、結論と次の操作だけを書く。
- エラーは「端末の仕組み」ではなく「ユーザーが何をしたかったか」から書く。例の方向性：「LINE が見つかりません」ではなく「LINE の通知がまだ届いていません。設定を開いて、通知をオンにしますか？」のように選択肢を出す（実際の挙動が決まってから）。
- 空の画面は「何ができるようになるか」まで（RealMatch 型）。Soto Map の記録が空なら「まだ記録がありません。出かけた場所を残すと、ここで振り返れます」など。
- サイトは今まさに「新旧が混在」している（A/B のパターン、旧ページ、コラム約70本）。本の勧めどおり、**変える前にスタイルガイド（このノート）を完成させ、残すもの・変えるものを決めてから一括で直す**のが正しい順番。ブランド名が未定のうちは、名前に依存しない部分（フォーム、エラー、成功、404）から手を付けるのが安全。

### ロイヤルカスタマーは、同時にターゲット顧客でもあります（p.265）
- 多くの組織は、まあまあ用が足りるか、やや不満のあるシステムで間に合わせている。それでもユーザーに最良の体験を届けたいなら、イスラエル司法省の UX/UI リーダー、エリノア・ミシャン・サロモンの言葉：「彼らはまさにロイヤルカスタマー。意欲的に仕事をしている途中で、次にやるべきことが分からず立ち往生することなど、あってはならない。必要なのは最良の友としてのツールではなく、作業を滞らせることなく、彼らのために性能を発揮してくれるツール」。
- 満足すれば、もっと活用し、アドオンを買い、評判を広め、契約を更新する。それがあなたの ROI。

### なぜ複雑なシステムにボイス＆トーンのデザインが必要か（p.267〜269）
- 大事なのは読んで楽しいテキストではなく、ユーザーと、ユーザーが操作する状況に似合うボイス＆トーンをデザインすること。**正確で飾り気のないマイクロコピーは個性に欠ける、は間違い。飾り気がなく正確ということが個性**。不確定要素、プレッシャー、責任、締切、不安を抱えている人にはなおさら。シンプルで明快なマイクロコピーは、悲しい表情の顔文字よりずっと共感的。
- では常に真面目で正確でなければならないか？ いいえ。**仕事の現場にも遊び心を**：Mailchimp「やったね！ メールの送信時間が指定されました」「ハイタッチ！ メールが送信ボックスに入りました」、エラー「その名前のユーザーはすでに存在します。あなたの悪魔の双子かも…不気味ですね」。心理的に複雑で技術的に厳しい状況でも、人間味のある友好的な言葉で対応できる。ただし、直面しうるあらゆるシナリオと状況への感受性と、的確で完成度の高いボイス＆トーンが欠かせない。Trello、Slack も手本。
- **Salesforce の Voice and Tone スタイルガイド**（"Salesforce voice and tone" で検索）が B2B の手本。各事例に「オーディエンス」「ゴール＆トーン」を書く形式：
  - 事例3 ウィジェットの説明文（管理職層向け）：「ウィジェットを利用すると…時間の節約になります。1回作れば、繰り返し使えます」。ゴールは何かと利点を素早く伝えること。トーンは会話体で直接的、ただし過度にくだけない。
  - 事例6 開発者向けクイックスタート「おしゃべりは終わり：本題に入りましょう」。読者があまり読みたくないという事実を認め、簡潔に要点を押さえる。
- あらゆる専門的・複雑なシステムにぴったりの、ただひとつのボイス＆トーンはない。ブランドの個性、目的、ターゲット、関係性、作業環境で変わる。だから**一般向けでも専門家向けでも、真っ先にボイス＆トーンを特定することが、つねに必要**。第1章に完全ガイドがある。「読書の時間は終わりました。さあ、実践に移りましょう」。

## 27. 日本の読者に向けて（仲野佑希、p.270〜271）
- 懸念は「異なる文章の作法を持つ日本でも使えるか」だったが、余計な心配だった。基本はユーザーとの対話。ハイコンテクストで曖昧さを好む日本人にとって、言葉に表すことはとても繊細なプロセスであり、専門家が要る。
- 日本語のルールと作法（ひらがな、カタカナ、漢字、アルファベットの使い分け）を身につけつつ、ルールにとらわれすぎない。**ボイス＆トーンに基づき、相手に効果的に伝わる、生きた言葉を用いることは作法以上に大事**。
- 生きた言葉のために、日ごろからインターフェイスの言葉に注意を：ゲーム、ATM、漫画家のキャラクターの言葉、Siri やアレクサの返答。あらゆるところにヒントがある。
- コミュニティ：世界最大の Facebook グループ『Microcopy & UX Writing』（1万5000人超）、日本版『Microcopy & UX Writing Japan』。
- UX ライターの需要は DX で拡大（Booking.com はデザイナー5〜6人に UX ライター1人でも足りない）。チャットボットや音声アシスタントで「会話」そのものがインターフェイスになりつつある今、テクノロジーに温もりと人間らしさを与えることが AI 時代のライターに求められるスキル。

**Soto への示唆（本全体の締めくくりとして）：**
- 「飾り気がなく正確ということが個性」は、Soto の静かな人格そのもの。無理に面白くしなくてよい。正確で短い言葉が、Soto らしさになる。遊び心は Mailchimp のように「完了した瞬間」の一言に限って、まれに。
- Salesforce 形式（オーディエンス／ゴール＆トーン／例文）は、Soto のスタイルガイドの書き方としてそのまま使う。場面ごと（トップの見出し、登録フォーム、エラー、成功、端末の通知、Instagram の投稿）に「誰に・何のために・どんな調子で・例」を1枚ずつ。
- 日本語の作法：ひらがな・カタカナ・漢字・英語の使い分けのルールを、スタイルガイドに入れる（例：「Soto Map」などの英語表記と日本語の併記、漢字を開く語の一覧、数字は半角など）。サイトは今、ほぼ一貫しているので、それを明文化する。
- 本の結論どおり、**次は実践**：このノートを、場面別のスタイルガイドに作り替え、名前に依存しない部分（フォーム、エラー、成功、404）から直す。
