# スマートウォーク 企画書・仕様書

## 1. コンセプト

依存系アプリ（SNS・動画・ゲーム等）を、ユーザーが指定した「解除スポット」に
到着するまでロックする、デジタルデトックス × 外出促進アプリ。

- 引きこもり・在宅ワーク民の「外出動機の欠如」「食生活の乱れ」「スマホ依存」の
  悪循環を断つ。
- 解除スポット（スーパー・カフェ等）に企業が出稿することで、来店促進ツールとして
  機能する。

## 2. ターゲット

- 在宅ワーカー、引きこもり傾向のある人
- スマホ依存を自覚し、自分を物理的に動かす仕組みが欲しい人
- セルフコントロール系アプリ（スクリーンタイム強化）に課金する層

## 3. 機能仕様（MVP）

### 3.1 ユーザー向け機能

| 機能 | 内容 |
|---|---|
| 認証 | Family Controls の個人モード（`.individual`）認可をリクエスト |
| 対象アプリ選択 | `FamilyActivityPicker` でロックするアプリ/カテゴリを選択 |
| 解除スポット選択 | スポット一覧（MVPはスーパー）から目的地を選択 |
| ロック | 自宅など解除エリア外では対象アプリを `ManagedSettings` でシールド |
| 自動解除 | GPSジオフェンスで解除スポット到着を検知 |
| 滞在判定 | 解除スポット圏内に**連続3分**滞在して初めてシールド解除（通り過ぎ・素通りを除外）|
| 再ロック | 解除スポットの圏外に出たら（＝帰宅したら）再シールド |

### 3.2 状態遷移

```
[ロック中] --スポット圏内に入る(didEnterRegion)--> [滞在中: タイマー開始]
[滞在中]   --連続3分滞在--------------------------> [解除中]
[滞在中]   --3分未満で圏外に出る(didExitRegion)--> [ロック中: タイマーリセット]
[解除中]   --スポット圏外に出る(didExitRegion)----> [ロック中]
アプリ起動時: 現在地を評価して初期状態を決定
```

滞在必要時間（既定3分）は設定値。値を上げるほど「素通り解除」を防げるが、
ユーザーの負担も増えるためA/Bで調整する。来店滞在を要件にすることで、
企業の来店促進ツールとしての価値（実来店の担保）も高まる。

### 3.3 MVPの割り切り

- iOS 先行（Android はスクリーンタイム相当APIの制約が異なるため後回し）
- 解除スポットは「スーパー」カテゴリのみ
- スポットは運営があらかじめ登録した固定リスト（動的な企業出稿は次フェーズ）

## 4. 技術スタック

- Swift / SwiftUI（iOS 16.0+）
- **FamilyControls** … 認可、対象アプリ選択UI
- **ManagedSettings** … 実際のシールド（ロック）適用
- **DeviceActivity** … スケジュール監視（再ロックの保険／利用状況）
- **CoreLocation** … `CLCircularRegion` によるジオフェンス監視
- App Group … 本体アプリと拡張機能間の状態共有

詳細な実装とXcodeプロジェクトの組み立ては `ios/SETUP.md` を参照。

## 5. Family Controls エンタイトルメント申請

- 配布には Distribution 版 `com.apple.developer.family-controls` の Apple 承認が必要。
- 申請: https://developer.apple.com/contact/request/family-controls-distribution
- 開発・TestFlight 段階は Xcode の Capability 追加だけで検証可能。
- 申請理由には「ユーザー本人が自分の端末を自己制限する用途」であることを明記する
  （親→子の管理用途ではない点を強調するとレビューがスムーズ）。

## 6. 収益モデル

企業（スーパー・カフェ等）が「解除スポット」として出稿する。
ヒアリング時点で2案あり、要確定。

### 案A: 月額固定
- 月額 5万円で、優先的にゴール地点として誘導表示。

### 案B: タイムシェア型（時間枠課金）
- タイムズシェアのように「誘導したい時間枠」を15分単位で購入。
- 規模別単価:

| 規模 | 15分あたり |
|---|---|
| 小規模 | 500円 |
| 中規模 | 1,000円 |
| 大規模 | 1,400円 |

### 確定すべき論点
- 案Aと案Bは併存させるのか、どちらかに絞るのか
- 「優先表示」のロジック（課金額順？ 距離との重み付け？）
- **App Store ガイドライン対応**: 課金額で誘導順位が変わる場合、ユーザーに
  「スポンサー枠／広告である」旨を明示する必要がある（非開示はリジェクト対象）。

## 7. プライバシー / 審査リスク

- 位置情報は常時取得（`Always` 認可）が必要 → 用途説明を Info.plist と
  審査ノートに明記。
- Screen Time API は「自己制限」用途で使用。レビュアー向けに動作手順を明記。
- 解除スポットの優先表示は広告であることをアプリ内で開示。
